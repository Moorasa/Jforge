## 4. 화면 조립 계약 (중요)
MagicIAM의 "관리화면 1개"는 실제로 **여러 3종 세트를 iframe으로 오케스트레이션**한 것:
- shell `{stem}.jsp` (layout header/menu/breadcrumb include + common/header.jsp)
- `{stem}List.jsp`(+js/css) : 뷰 전환 컨트롤러(commonList)
- `{stem}ListTableView.jsp`(+js/css) 등 뷰별 세트
- Detail 영역: basic-info + associate-info(탭→iframe)
→ 생성기는 "1 화면 = N개의 3종 세트 + include 배선"을 산출해야 한다.

## 5. 데이터 모델 (PostgreSQL, MagicIAM 네이밍: 대문자 스네이크/_CODE/_ID/_YN)
- `TB_FRG_PROJECT` : PROJECT_ID, PROJECT_NAME, TARGET_ROOT_PATH, PACKAGE_BASE,
  JSP_BASE_PATH, JS_BASE_PATH, CSS_BASE_PATH, DB_TYPE_CODE, RUNTIME_VER, USE_YN
- `TB_FRG_SCREEN` : SCREEN_ID, PROJECT_ID, SCREEN_NAME, STEM, ARCHETYPE_CODE,
  ROLE_CODE(admin/user), DEFINITION_JSON(설계 문서=source of truth), STATUS_CODE
- `TB_FRG_MODULE_TYPE` : MODULE_TYPE_CODE, MODULE_NAME, CATEGORY_CODE,
  PROP_SCHEMA_JSON(속성패널 스키마), TEMPLATE_KEY, PREVIEW_KEY  ← 팔레트 카탈로그(시드)
- `TB_FRG_GEN_HIST` : GEN_HIST_ID, SCREEN_ID, GEN_AT, FILE_LIST_JSON, RESULT_CODE
- `TB_FRG_COMMON_CODE` : GRP_CODE, CODE, CODE_NAME, SORT_ORDER, USE_YN
> 설계는 문서모델(DEFINITION_JSON)로 저장(유연). 모듈 카탈로그만 정규화.

## 6. 생성 엔진 파이프라인
DEFINITION_JSON → TemplateContext → FreeMarker 렌더(아티팩트별) → 경로 해석 → **원자적 파일쓰기** → GEN_HIST 기록
- 아티팩트: JSP/JS/CSS 3종 × N + (옵션)Controller stub + Mapper interface/XML stub
- **공통코드 처리(요구사항)**: 두 층위 —
  1) 런타임 공통(commonListTableView.js 등)은 타겟에 1회 동기화·버전관리(중복 생성 금지)
  2) 화면 간 반복 패턴(공통 컬럼셋/공통 팝업 등)은 per-screen 인라인이 아니라 **공통 파셜/상수로 추출**해 공유
- **경로 안전(보안 필수)**: TARGET_ROOT_PATH 하위로만 쓰기(경로 탈출 차단), 화이트리스트 확장자,
  기존 파일 덮어쓰기 전 diff/백업, 템플릿 인젝션 방지.

## 7. 빌더 UI (3-pane, MagicIAM 도그푸딩)
