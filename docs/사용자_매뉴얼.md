> 기준: 2026-08-04 (P0~P13 반영). 제품 배경은 [기획서](기획서_v0.1.md), 산출 규칙은
> [생성엔진 계약](생성엔진_계약.md)을 보세요. 이 문서는 **쓰는 방법**만 다룹니다.

## 0. J-FORGE가 하는 일

화면을 **조립**하면, 저장 시 JWorks 규약의 **JSP + JS + CSS 3종 세트**가 여러분의 타겟
프로젝트 폴더에 **직접 생성**됩니다. 손으로 화면을 짜지 않고, 부품을 골라 배치하고 속성을
채우는 방식입니다.

```
프로젝트 등록  →  화면 만들기  →  부품 배치·속성 편집  →  저장  →  파일 생성
   (한 번)        (화면마다)        (스튜디오)          (DB)      (타겟 폴더)
```

**접속 주소**: `http://localhost:18080/forge/admin`

## 1. 시작하기

### 1.1 사전 준비

| 항목 | 값 |
|---|---|
| 앱 주소 | `http://localhost:18080/forge` |
| DB | PostgreSQL, `jforge` 스키마 |
| 타겟 폴더 | 생성 파일을 받을 폴더 (미리 만들어 두세요) |

> **DDL 적용**: 이 프로젝트는 Flyway가 없습니다. `src/main/resources/db/ddl/V*.sql`을
> **번호 순서대로 직접 실행**해야 합니다. 새 버전을 받은 뒤 팔레트에 모듈이 안 보이거나
> 화면 유형이 없다면 십중팔구 DDL 미적용입니다.
>
> ```bash
> psql -U postgres -d postgres -f src/main/resources/db/ddl/V10__free_canvas.sql
> ```

### 1.2 화면 구성 (상단 메뉴)

| 메뉴 | 하는 일 |
|---|---|
| **대시보드** | 프로젝트/화면 개수, 사용 안내 |
| **프로젝트** | 타겟 폴더·패키지 등록, 타겟 DB 연결 |
| **모듈 카탈로그** | 사용 가능한 부품 목록과 속성 폼 미리보기 (읽기 전용) |
| **스튜디오** | 실제 화면을 조립하는 곳 |

## 2. 프로젝트 등록

`프로젝트` 메뉴에서 등록합니다. **프로젝트 = 생성 파일이 나갈 목적지**입니다.

| 입력 | 필수 | 설명 |
|---|---|---|
| **이름** | ✅ | 구분용 이름 |
| **타겟 루트 경로** | ✅ | **절대경로**여야 합니다 (예: `C:\parkDev\my-app`). 이 폴더 **아래로만** 파일이 써집니다 |
| **패키지 베이스** | ✅ | 생성될 Controller/Mapper의 자바 패키지 (예: `com.acme.app`). 소문자만 |

입력하면서 타겟 경로 아래에 `✓ 절대경로` 또는 경고가 표시됩니다.

### 2.1 수정·삭제

목록의 **수정** 버튼으로 값을 고칠 수 있습니다(등록 폼이 그 값으로 채워집니다). **삭제**는
논리삭제이며 **이미 생성된 파일은 지우지 않습니다.**

> 패키지 베이스가 비어 있으면 목록에 `미설정 — 생성 불가`로 표시되고 파일 생성이 거부됩니다.

### 2.2 타겟 DB 연결 (선택)

목록의 **DB 연결** 버튼. 연결해 두면 나중에 속성패널에서 **테이블·컬럼을 골라서** 화면을
만들 수 있어 오타가 사라집니다.

- host / port / database / schema / user / password를 조각으로 입력합니다.
  **JDBC URL은 받지 않습니다**(서버가 조립 — 드라이버 파라미터 주입 차단).
- **읽기전용 계정을 권장**합니다. 스키마 조회(테이블·컬럼)에만 씁니다.
- 비밀번호는 암호화 저장되며 화면에 다시 표시되지 않습니다. 비워두면 기존 값 유지.
- **연결 테스트**로 먼저 확인한 뒤 **저장**하세요.

## 3. 화면 만들기

스튜디오 상단 **새 화면**을 누릅니다.

| 입력 | 설명 |
|---|---|
| **화면 이름** | 목록에 보이는 이름 (한글 가능) |
| **파일 이름 (영문)** | 생성 파일명의 뿌리. 소문자로 시작, 영문/숫자만. 예: `userMgmt` → `userMgmt.jsp`, `userMgmtList.js` … |
| **화면 유형** | 아래 6종 중 하나 (아키타입) |
| **사용 영역** | `admin` / `user` — 생성 경로에 들어갑니다 |
| **기본 구성으로 시작** | 유형에 맞는 기본 부품을 미리 배치해 줍니다 (권장) |

### 3.1 화면 유형 6종

| 유형 | 구조 | 언제 |
|---|---|---|
| **관리 화면** | 검색 + 목록 + 상세 | 가장 일반적인 CRUD 화면 |
| **단순 목록** | 검색 + 목록 | 상세가 필요 없을 때 |
| **좌우 분할** | iframe 2단 + 리사이저 | 화면 두 개를 나란히 |
| **팝업** | 입력 폼 + 확인/취소 | 추가·수정 팝업 |
| **대시보드** | 위젯 나열 | 차트·현황판 |
| **자유 배치** | **고정폭 시트에 좌표로 배치** | 정해진 틀 없이 직접 그릴 때 |

> **유형은 나중에 바꿀 수 없습니다.** 화면을 새로 만들어야 합니다.

### 3.2 화면 관리 (⋯ 버튼)

- **이름 변경** — 화면 이름과 파일 이름 변경
- **복제** — 배치·속성을 그대로 복사해 새 화면 생성
- **삭제** — 논리삭제. **생성된 파일은 지우지 않습니다**

## 4. 스튜디오 사용법

화면은 3단입니다 — **좌: 팔레트 / 중: 캔버스 / 우: 속성**. 가운데 구분선을 드래그해 폭을
조절할 수 있습니다.

### 4.1 슬롯형 화면 (자유 배치를 제외한 5종)

부품은 **정해진 영역(슬롯)** 에만 들어갑니다.

1. 팔레트에서 **영역 이름**(검색영역·목록영역 등)을 클릭해 펼칩니다.
2. 그 영역에 넣을 수 있는 부품만 표시됩니다.
3. 부품을 **클릭**하면 배치됩니다. 후보 영역이 여러 개면 캔버스에서 하이라이트된 영역을
   클릭해 확정합니다 (Esc 취소).
4. 팔레트 항목을 캔버스 영역으로 **드래그**해도 됩니다.
5. 캔버스 영역 헤더의 **+ 모듈 추가**로도 넣을 수 있습니다.

**영역별 규칙**

- 영역마다 넣을 수 있는 **부품 종류**와 **개수**가 정해져 있습니다.
- `복수` 뱃지가 있으면 여러 개, 없으면 1개만. 1개짜리에 또 넣으면 **교체할지** 물어봅니다.
- **목록영역은 필수**입니다(관리 화면·단순 목록). 비우면 저장이 거부됩니다.
- **좌우 분할**의 좌·우 영역에는 **레이아웃 프레임만** 놓을 수 있습니다(그 자리가 iframe이라서).

**순서 바꾸기**: 같은 영역 안에서 블록을 드래그해 위아래로 옮깁니다.

**크기 조절**: 검색영역·목록툴바·목록영역만 우측(폭 %)·하단(높이 px) 핸들이 나옵니다.
나머지는 `크기 고정` 배지가 뜹니다 — **공통 레이아웃이 정하는 영역이라 조절해도 파일에
반영되지 않기 때문**입니다.

### 4.2 자유 배치 화면

델파이 폼처럼 **원하는 자리에 원하는 크기로** 놓습니다. 1280×800 고정폭 시트에 8px 격자가
깔립니다. **여기 보이는 픽셀이 그대로 생성 CSS로 나갑니다.**

**부품 놓기**

- 팔레트에 **전체 카탈로그**가 뜹니다(슬롯 필터 없음).
- 부품 클릭 → 캔버스에서 **놓을 자리 클릭**. 또는 팔레트에서 캔버스로 **드래그**.

**조작**

| 하고 싶은 것 | 방법 |
|---|---|
| 이동 | 블록 드래그 (8px 스냅) |
| 스냅 끄기 | **Alt** 누른 채 드래그 |
| 미세 이동 | 방향키 1px / **Shift**+방향키 8px |
| 크기 조절 | 선택 후 8방향 핸들 드래그 |
| 겹침 순서 | 블록 크롬의 **▲**(맨 앞) **▼**(맨 뒤) |
| 정확한 값 입력 | 속성패널의 **X / Y / W / H / Z** |

블록 크롬(모듈명·버튼)은 **마우스를 올리거나 선택했을 때만** 나타납니다. 평소엔 결과물
그대로 보입니다.

**패널(프레임)로 묶기**

팔레트의 **레이아웃 → 패널(프레임)** 을 놓으면 다른 부품을 담는 상자가 됩니다.

- **넣기**: 부품을 패널 위에 드롭하거나, 놓인 블록을 드래그해 패널 위로. 넣을 수 있는 패널은
  **초록 점선**으로 표시됩니다.
- **빼기**: 패널 밖으로 끌어내면 빠집니다.
- 패널을 옮기면 **안의 내용물도 함께** 움직입니다(자식 좌표가 패널 기준).
- 패널은 내용물을 **잘라냅니다**. 패널보다 큰 부품은 잘린 채 생성됩니다.
- 패널 안에 패널도 됩니다(**최대 3단계**).
- **패널을 지우면 안에 든 것도 함께 지워집니다** (Ctrl+Z로 되돌리기).

### 4.3 속성 편집 (우측 패널)

캔버스에서 부품을 클릭하면 우측에 3개 탭이 나옵니다.

**① 속성 탭** — 부품마다 다른 설정(컬럼 목록, 버튼 목록, 필터, 제목 등). 부품별 항목은
`모듈 카탈로그` 메뉴에서 미리 볼 수 있습니다.

**② 데이터 탭** — 이 부품이 어떤 API에서 데이터를 가져올지

| 항목 | 설명 |
|---|---|
| 데이터 바인딩 사용 | 켜야 나머지가 적용됩니다 |
| API 경로 | 같은 앱의 절대경로만 (예: `/api/users`) |
| 요청 방식 | GET / POST |
| 결과 경로 | 응답 JSON에서 배열이 있는 키 (예: `items`) |
| 화면 진입 시 자동 조회 | 켜면 로드 즉시 조회 |
| **테이블 / 키 컬럼** | 채우면 **생성 시 Controller·Mapper·SQL이 실제 조회 API로 만들어집니다** (비우면 빈 껍데기) |

**테이블에서 컬럼 가져오기** 버튼 — 프로젝트에 DB를 연결해 뒀다면 테이블 목록에서 고르고
→ 컬럼을 체크하면 **컬럼 목록이 자동으로 채워집니다.** 키 컬럼도 여기서 지정합니다.

**③ 이벤트 탭** — 클릭·값 변경·선택에 대해 `다시 조회 / 상세 열기 / 저장 / 사용자 정의`
동작을 연결합니다.

### 4.4 단축키

| 키 | 동작 |
|---|---|
| `Ctrl+S` | 저장 (입력 중에도 동작) |
| `Ctrl+Z` | 실행 취소 |
| `Ctrl+Y` / `Ctrl+Shift+Z` | 다시 실행 |
| `Ctrl+D` | 선택 부품 복제 |
| `Delete` | 선택 부품 삭제 |
| `Esc` | 배치 대기 취소 |

## 5. 저장과 생성 — 다른 일입니다

| | **저장** | **파일 생성** |
|---|---|---|
| 하는 일 | 설계를 **빌더 DB**에 기록 | 타겟 폴더에 **실제 파일 쓰기** |
| 버튼 | 저장 (Ctrl+S) | 파일 생성 |
| 되돌리기 | Ctrl+Z | 백업에서 복원 |

**저장하지 않으면 생성에 반영되지 않습니다.** 상단에 `● 미저장`이 떠 있으면 먼저 저장하세요.

### 5.1 실행 미리보기

**저장된 설계**를 실제 마크업·런타임으로 새 탭에서 보여줍니다. 타겟 앱을 띄우지 않아도
됩니다. 캔버스는 편집용 근사치이고, 이쪽이 결과물에 가깝습니다.

### 5.2 파일 생성 (dry-run → 확정)

**파일 생성**을 누르면 바로 쓰지 않고 **계획 모달**이 먼저 뜹니다.

- `신규 n · 덮어쓰기 m` 요약
- 파일별 경로와 `신규` / `덮어쓰기` 태그
- **`외부 수정됨`** 태그 — 마지막 생성 이후 **사람이 손댄 파일**입니다
  - **변경 보기**를 누르면 줄 단위 diff를 보여줍니다
  - **되돌리기**로 이전 백업 시점을 골라 복원할 수 있습니다 (복원도 백업됩니다)

확인 후 실행하면 하단에 **생성 결과**와 파일 목록이 나오고, **생성 이력**에 기록됩니다.

### 5.3 무엇이 생성되나

화면 유형에 따라 다르지만 공통적으로:

- **화면 3종**: `{stem}.jsp` / `{stem}.js` / `{stem}.css` (유형에 따라 List·Detail 세트 추가)
- **번들 런타임**: jQuery, jworks 위젯, commonList*·commonSection 등 — 타겟에 **1벌만** 동기화
- **서버 stub**: Controller / Mapper / Mapper XML
  - 데이터 탭에 **테이블**을 채웠으면 → 실제 조회 코드
  - 안 채웠으면 → 빈 껍데기

> **자유 배치는 항상 3파일**입니다. 같은 부품을 몇 개 놓아도 마찬가지입니다.

## 6. 생성된 코드를 고칠 때

| 고치려는 것 | 어디서 | 재생성하면 |
|---|---|---|
| 화면 배치·속성 | 스튜디오 | 반영됨 ✅ |
| 모든 화면 공통 스타일/동작 | 빌더 저장소 `static/**/common/` | 반영됨 ✅ (아래 주의) |
| Controller·Mapper 로직 | 타겟 프로젝트 | **보호구역 안이면 보존** ✅ |
| 생성된 JSP/JS/CSS | 타겟 프로젝트 | **덮어씀** ⚠ |

### 6.1 보호구역 (Java·XML만)

생성된 Controller/Mapper/XML에는 이런 표시가 있습니다:

```java
// <j-forge:custom id="...">
   여기 쓴 코드는 재생성해도 보존됩니다
// </j-forge:custom>
```

**마커 밖에 쓴 코드는 덮어씁니다.** JSP/JS/CSS에는 아직 보호구역이 없습니다.

### 6.2 공통 CSS/JS 고치기

1. `src/main/resources/static/css/admin/common/` 또는 `.../js/admin/common/` 편집
2. **`RuntimeSyncer.RUNTIME_SET_VERSION` 상수를 올립니다** ← 빠뜨리기 쉬움
3. 화면을 생성하면 타겟에 동기화됩니다

> 버전을 안 올리면 타겟 마커와 같아서 **조용히 건너뜁니다.** 고쳤는데 반영이 안 되면
> 이걸 먼저 확인하세요. 파일을 **새로 추가**하려면 `RUNTIME_RELATIVE_PATHS` 목록에도
> 넣어야 합니다.
>
> 공통은 **화면 단위로 퍼집니다.** 기존 화면에 반영하려면 그 화면들을 각각 다시

## 7. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| 팔레트에 모듈이 안 보임 | **DDL 미적용**. `V*.sql`을 순서대로 실행 후 하드리프레시 |
| 화면 유형에 "자유 배치"가 없음 | 위와 동일 (V10) |
| `패키지 베이스가 비어 있습니다` | 프로젝트 → **수정** → 패키지 베이스 입력 |
| `targetRootPath는 절대경로여야 함` | `C:\...` 처럼 절대경로로 입력 |
| 저장 버튼이 비활성 | 변경이 없거나 화면 미선택. `● 미저장`이 떠야 활성 |
| 크기 조절 핸들이 없고 `크기 고정` | 그 영역은 공통 레이아웃 소관 — 조절해도 파일에 안 나가서 막아둔 것 |
| 생성 결과가 `PARTIAL` | 일부 파일 실패. 하단 결과 목록에서 실패 항목 확인 |
| 공통 CSS를 고쳤는데 반영 안 됨 | `RUNTIME_SET_VERSION` 미증가 (§6.2) |
| 화면이 안 바뀜 | 브라우저 캐시. **Ctrl+Shift+R** |
