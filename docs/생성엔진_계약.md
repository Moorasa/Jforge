# 생성 엔진 파이프라인 계약 (P4-0)

> J-FORGE **P4 생성 엔진**이 `DEFINITION_JSON`(P3 산출) 1건을 입력받아 타겟 프로젝트 폴더에 **JSP+JS+CSS 3종 세트**를 안전하게 쓰기까지의 **단일 계약**이다.
> 이 문서는 P4-1~P4-7 전 태스크가 공유하는 계약이므로 **다른 P4 코드보다 먼저 고정**한다(P3-2 선례: 계약 선행으로 재작업 방지).
> 계약 위반(자유문자열 원문 삽입·경로 조립에 자유문자열 포함·PathSafetyService 미경유·TEMPLATE_KEY 문자열 조립)은 **reviewer blocker**다.

## 1. 아티팩트 매핑 계약

MVP 기준: **`archetype=MGMT_LIST_DETAIL`** + **`listArea`에 배치된 `TABLE_VIEW` 1뷰**. 기획서 4장 조립 계약 `shell → List → List{View}`에 대응한다.

### 1.1 산출 아티팩트 → 파일 목록

파일명은 전부 **`{정적접미사}` + `stem`** 조립뿐이다(stem은 §1.1 정규식 통과값, §4.2). props값·instanceId·label 등 자유문자열은 **파일명에 절대 미포함**.

| # | 아티팩트 | 템플릿(TEMPLATE_KEY/키) | 산출 파일명 | 종류 | 비고 |
|---|---|---|---|---|---|
| 1 | shell | `archetype/mgmtListDetail/shell` | `{stem}.jsp` | JSP | layout include + `common/header.jsp` 매니페스트 참조 + List 컨테이너/iframe 배선 |
| 2 | List (JSP) | `archetype/mgmtListDetail/list` | `{stem}List.jsp` | JSP | 뷰 전환 컨트롤러(commonList 참조), searchArea/listToolbar 조건부 |
| 3 | List (JS) | `archetype/mgmtListDetail/listJs` | `{stem}List.js` | JS | `window.MagicIAM_JS{Domain}{Role}` 네임스페이스+IIFE+`__defined` |
| 4 | List (CSS) | `archetype/mgmtListDetail/listCss` | `{stem}List.css` | CSS | |
| 5 | ListTableView (JSP) | `module/tableView` | `{stem}ListTableView.jsp` | JSP | TABLE_VIEW props(columns/selectMode/pagingYn/excelYn/csvYn) 반영 |
| 6 | ListTableView (JS) | `module/tableViewJs` | `{stem}ListTableView.js` | JS | commonListTableView 참조 |
| 7 | ListTableView (CSS) | `module/tableViewCss` | `{stem}ListTableView.css` | CSS | |

> **접미사 확정 규칙**: List 세트는 `List`, TABLE_VIEW 세트는 `ListTableView`(뷰코드 `TableView`가 `List`에 이어붙음). 뷰코드는 `moduleTypeCode`가 아니라 **정적 매핑표**(`TABLE_VIEW→TableView`)에서 얻는다(문자열 조립·평가 금지, §4.4와 동형).
> stub(`{Stem}Controller.java`/`{Stem}Mapper.java`/`.xml`)은 **P4-6**에서 다룬다. 본 계약의 §4는 stub 경로 조립에도 그대로 적용된다.
> searchArea(SEARCH_FILTER_BAR)/listToolbar(TOOLBAR) 슬롯은 존재 시에만 shell/List 내부에 조건부 렌더(별도 파일 산출 아님, MVP). 미배치 시 깨지지 않아야 한다.

### 1.2 타겟 상대경로 결정 규칙

`resolveSafeWritePath(targetRoot, relativePath)`에 넘길 **relativePath**를 아래 규칙으로 결정한다. `role`(admin/user)과 프로젝트 메타 basePath를 조합하되, **경로 세그먼트는 전부 정적 + stem뿐**이다.

| 종류 | basePath 소스(프로젝트 메타) | relativePath 규칙 |
|---|---|---|
| JSP | `JSP_BASE_PATH` | `{JSP_BASE_PATH}/{role}/{stem}/{파일명}.jsp` |
| JS | `JS_BASE_PATH` | `{JS_BASE_PATH}/{role}/{stem}/{파일명}.js` |
| CSS | `CSS_BASE_PATH` | `{CSS_BASE_PATH}/{role}/{stem}/{파일명}.css` |
| stub(java, P4-6) | `PACKAGE_BASE`→폴더 | `{PACKAGE_BASE 폴더}/{domain}/{Stem}Controller.java` 등 |

- basePath·role·stem은 **모두 화이트리스트 통과값**(basePath는 프로젝트 메타의 정적 설정, role은 ROLE 공통코드 실존, stem은 §1.1 정규식). 자유문자열 아님.
- `{role}` 하위 세그먼트를 basePath에 붙일지(`{JSP_BASE_PATH}/{role}/...`)와 `{stem}` 폴더 분리 여부는 프로젝트 관례에 맞추되, **본 계약은 위 형태를 기본**으로 한다. 어떤 조합이든 결과 relativePath는 §4를 통과해야 최종 유효.
- 최종 절대경로는 **항상** `resolveSafeWritePath`가 반환한 값만 사용(직접 `resolve`/문자열 연결로 절대경로를 만들지 않는다).

## 2. TemplateContext 계약

`TemplateContextBuilder`(P4-2)가 `ForgeScreen`(DEFINITION_JSON 원문) + `ForgeProject`(메타)를 FreeMarker 모델 `Map<String,Object>`로 변환한다. DEFINITION_JSON은 Jackson `readTree`로 **데이터로만** 파싱(문자열 조립·코드 평가 금지).

### 2.1 노출 모델 키 (템플릿 최상위)

| 키 | 타입 | 소스 | 설명 |
|---|---|---|---|
| `stem` | String | 화면 메타 `STEM`(§1.1 정규식 재검증) | 파일명·식별자 접두. |
| `role` | String | 화면 메타 `ROLE_CODE` | `admin`/`user`. 경로·네임스페이스. |
| `archetype` | String | 화면 메타 `ARCHETYPE_CODE` | `MGMT_LIST_DETAIL` 등. |
| `packageBase` | String | 프로젝트 `PACKAGE_BASE` | stub·JS 네임스페이스 파생. |
| `jspBasePath` | String | 프로젝트 `JSP_BASE_PATH` | 참조 경로 산출용(파일쓰기 경로는 §1.2). |
| `jsBasePath` | String | 프로젝트 `JS_BASE_PATH` | |
| `cssBasePath` | String | 프로젝트 `CSS_BASE_PATH` | |
| `runtimeVer` | String | 프로젝트 `RUNTIME_VER` | 번들 런타임 버전(참조·주석용). |
| `slots` | Map<String, List<Instance>> | DEFINITION_JSON `slots` | 슬롯키 → 인스턴스 배열(배열 순서=렌더 순서). |

### 2.2 slots → instance → props 접근 (맵 조회 전용)

- `slots`는 **맵**이다. 템플릿은 `slots["listArea"]`, `slots["searchArea"]`처럼 **슬롯키를 리터럴 상수로만** 조회한다. 슬롯키를 변수로 문자열 조립하지 않는다.
- 각 `Instance`는 맵으로 노출: `instanceId`(String), `moduleTypeCode`(String), `props`(Map<String,Object>).
- props 값 접근도 **맵 조회**: `props["columns"]`, `props["selectMode"]` 등. props 키를 문자열로 조립·코드 평가하지 않는다(DEFINITION_JSON §5.1, PROP_SCHEMA §2.1 재사용).
- 반복행(`columns`/`filters`/`buttons`)은 `List<Map<String,Object>>`. 행 값 접근도 맵 조회(`row["displayName"]`, `row["label"]`, `row["styleClass"]`).
- forward-compat(§4 of DEFINITION_JSON): 미지원 slotKey/moduleTypeCode 인스턴스는 컨텍스트 구성 단계에서 **스킵+로그**(문서 전체 실패 금지). 미지원 props 키 무시.

> **원칙**: TemplateContext의 어떤 값도 "식별자/코드로 평가"되지 않는다. 전부 데이터 맵으로만 노출하고, 템플릿은 리터럴 키로만 접근한다. 이것이 템플릿 인젝션의 1차 차단이다.

### 2.3 🔒 엔진측 위험 빌트인 차단 (P4-1 필수 설정)

데이터를 데이터로만 노출해도 **템플릿 코드 측** 빌트인이 자유문자열을 코드로 승격시킬 수 있으므로, `CodeGenTemplateConfig`(P4-1)는 아래를 **엔진 설정으로 강제**한다(2차 차단).

- `Configuration.setNewBuiltinClassResolver(TemplateClassResolver.ALLOWS_NOTHING_RESOLVER)` — `?new`(임의 클래스 인스턴스화) 차단.
- `?eval`/`?interpret`/`?api` 등 문자열→코드 승격 빌트인을 템플릿에서 사용하지 않으며(코드리뷰로 강제), 신뢰된 내부 템플릿만 로딩(외부/사용자 템플릿 로딩 금지).
- `TemplateExceptionHandler.RETHROW_HANDLER`(생성 실패를 조용히 삼키지 않음).

## 3. 🔒 이스케이프 정책 (핵심)

DEFINITION_JSON §5 재사용: **서버는 props 자유문자열을 이스케이프하지 않는다. 소비자=P4가 산출 문맥에 맞게 이스케이프한다.** props 자유문자열(label/displayName/styleClass/options/컬럼값 등)이 산출물의 어느 문맥에 들어가는지 분류하고, 문맥별 이스케이프 함수를 지정한다.

### 3.1 자유문자열 원천 (props 값)

| 원천 | 모듈 | 성격 | 대표 삽입 문맥 |
|---|---|---|---|
| `columns[].displayName` | TABLE_VIEW | 표시 라벨 | HTML 텍스트, JS 문자열 |
| `columns[].name` | TABLE_VIEW | 필드명(표시·바인딩) | HTML 속성, JS 문자열 |
| `filters[].label` / `.name` / `.options` | SEARCH_FILTER_BAR | 라벨/필드명/옵션문자열 | HTML 텍스트·속성, JS 문자열 |
| `buttons[].label` | TOOLBAR | 버튼 라벨 | HTML 텍스트 |
| `buttons[].actionCode` | TOOLBAR | 액션코드 | HTML 속성(`data-action`), JS 문자열 |
| `buttons[].styleClass` / 기타 styleClass류 | TOOLBAR 등 | CSS 클래스 토큰 | HTML `class` 속성 = CSS 토큰 |

> 위 값들은 §5 신뢰경계상 **서버가 검증·이스케이프하지 않은 자유문자열**이다. 어떤 값도 이스케이프 없이 원문 삽입할 수 없다.

### 3.2 문맥별 이스케이프 함수 (P4-2가 이 이름으로 구현)

| 함수명 | 적용 문맥 | 처리 내용 |
|---|---|---|
| `htmlText` | HTML 요소 텍스트 노드 (`<td>여기</td>`, `<button>여기</button>`) | `&`→`&amp;`, `<`→`&lt;`, `>`→`&gt;` (필요시 `"`/`'`도). |
| `htmlAttr` | HTML 속성값 (`data-name="여기"`, `class="여기"`) | `&`/`<`/`>`/`"`/`'` 엔티티화(`"` 엔티티화는 **항상 수행 — 옵션 아님**). **속성은 항상 쌍따옴표로 감싼다**(템플릿 규약, unquoted 속성 금지 §3.3). |
| `jsString` | JS 문자열 리터럴 내부 (`var x = '여기';`) | `\`→`\\`, `'`→`\'`, `"`→`\"`, `/`→(특히 `</`는 `<\/`로), `\n`/`\r`→`\n`/`\r`, `U+2028`/`U+2029`→` `/` `. 인라인 `<script>` 산출 시 `<`를 `\x3C`로 이스케이프(권장, 문맥 무관 견고). 삽입 지점은 항상 따옴표 안. |
| `cssToken` | CSS 식별자/클래스 토큰 (`class="{여기}"`, CSS 선택자) | **화이트리스트 검증**: 허용 문자 `[A-Za-z0-9_-]`(공백 구분 다중 클래스 허용 시 토큰 단위로 각각 검증). **공백·`<`·`>`·`"`·`{`·`}` 배제**. 위반 토큰은 **드롭**(또는 하드 거부, §3.4). 유효 토큰만 통과. |

- FreeMarker에서 함수는 `TemplateMethodModel`/커스텀 디렉티브로 등록해 `${jsString(row["displayName"])}` 형태로 호출하거나, 출력 포맷 자동이스케이프(HTML)와 병행한다. **자유문자열은 반드시 위 함수 중 하나를 거친다.**
- `styleClass`류는 HTML `class` 속성이면서 동시에 CSS 토큰이므로 **`cssToken`으로 검증 후** `class="{...}"`에 삽입한다(공백 다중 클래스는 토큰별 검증).

### 3.3 "어떤 자유문자열도 이스케이프 없이 원문 삽입 금지" 원칙 표

| 산출 문맥 | 필수 함수 | 원문 삽입 |
|---|---|---|
| JSP/HTML 텍스트 노드 | `htmlText` | 🔒 금지 |
| JSP/HTML 속성값 | `htmlAttr` | 🔒 금지 (**unquoted 속성 금지** — 항상 쌍따옴표로 감쌈) |
| JS 문자열 리터럴 | `jsString` | 🔒 금지 |
| CSS 클래스/식별자/토큰 | `cssToken`(화이트리스트) | 🔒 금지 |
| 파일명·경로 세그먼트 | (자유문자열 삽입 자체 금지, §4) | 🔒 금지 |

> 이스케이프 함수를 거치지 않은 자유문자열이 산출물에 한 곳이라도 들어가면 **reviewer blocker**(인젝션 회귀 대상, P4-7 골든 고정).

### 3.4 위반 토큰 처리 정책

- `cssToken` 화이트리스트 위반: **기본 = 해당 토큰 드롭 + 경고 로그**(다중 클래스에서 유효 토큰은 살림). 전량 위반으로 빈 값이 되면 `class` 속성 자체를 생략.
- `htmlText`/`htmlAttr`/`jsString`: 위반이라는 개념 없이 **전량 이스케이프**(모든 입력을 안전 리터럴로 변환). 드롭하지 않는다.

## 4. 🔒 경로/파일명 안전 계약

### 4.1 최종 방어선 = PathSafetyService

- **모든 파일쓰기(3종 + stub + 런타임 복사)는 예외 없이** `PathSafetyService.resolveSafeWritePath(Path targetRoot, String relativePath)`를 통과해 반환된 절대경로만 사용한다.
- `targetRoot` = 프로젝트 `TARGET_ROOT_PATH`(반드시 존재하는 절대 디렉터리).
- 이 서비스가 차단하는 것(코드 인용): 콜론(`:`)/드라이브/ADS, UNC(`\\host`)·루트앵커(`/`,`\`), 명시적 `..`, 정규화 후 루트 탈출, 심볼릭링크 루트탈출, **확장자 화이트리스트 밖**. 위반 시 `PathSafetyException`.
- **확장자 화이트리스트**: `DEFAULT_ALLOWED_EXTENSIONS = {jsp, js, css, java, xml}`(코드 상수). 3종은 jsp/js/css, stub은 java/xml. 그 외 확장자로 쓰지 않는다.

### 4.2 파일명 조립 규칙

- 파일명 = **`{정적접미사}` + `stem`** 뿐. `stem`은 DEFINITION_JSON §1.1 정규식 `^[a-z][a-zA-Z0-9]*$` 통과값(파일명·식별자 안전).
- **이중 경계**: (1차) 화면 저장 시 stem 정규식 검증 → (2차) P4에서 `resolveSafeWritePath`가 canonical 정규화+루트하위 검증. 정규식 통과가 경로안전을 대체하지 않는다.
- stem 재검증: P4-2가 화면 메타 stem을 §1.1 정규식으로 **다시** 통과시킨 뒤에만 파일명/컨텍스트에 쓴다. 위반 시 **하드 실패**(경로 오염 차단). 메타 stem ↔ DEFINITION 내부 stem 불일치 시 정책은 P4-2에서 확정(메타 우선 + 경고 또는 하드실패).

### 4.3 relativePath에 자유문자열 절대 미포함

- relativePath의 어떤 세그먼트에도 **props값/instanceId/label/displayName/styleClass 등 자유문자열을 넣지 않는다.**
- 허용 세그먼트: 정적 문자열, `role`(ROLE 공통코드 실존), `stem`(정규식 통과), 프로젝트 메타 basePath/PACKAGE_BASE(정적 설정값).
- instanceId는 §1.3상 형태 정규식만 통과할 뿐 예약어 충돌 등을 막지 않으므로 **파일명·경로에 쓰지 않는다**(맵 키 조회로만 사용).

### 4.4 TEMPLATE_KEY → 템플릿 파일 해석 (맵 조회 전용)

- 템플릿 `.ftl` 해석은 **맵 조회로만** 한다. moduleTypeCode/archetype으로 문자열을 조립해 파일명을 만들지 않는다.
- 모듈 템플릿: `TB_FRG_MODULE_TYPE.TEMPLATE_KEY`(V3 시드) 확정값을 맵으로 조회 — `TABLE_VIEW→module/tableView`, `SEARCH_FILTER_BAR→module/searchFilterBar`, `TOOLBAR→module/toolbar`. 여기에 아티팩트 접미사(`Js`/`Css` 또는 확장자)를 붙여 실제 `.ftl`(예: `module/tableView.ftl`, `module/tableViewJs.ftl`) 해석.
- 아키타입 shell/List 템플릿: §1.1의 템플릿 키 컬럼(`archetype/mgmtListDetail/*`)을 아키타입 코드→키 **정적 매핑표**에서 조회.
- 뷰코드 매핑(`TABLE_VIEW→TableView`)도 정적 매핑표 조회(§1.1). 이 값들은 화이트리스트 밖이면 오류로 처리, 문자열 평가 경로를 만들지 않는다.

## 5. 덮어쓰기 / 원자성 / 이력 정책

### 5.1 원자적 쓰기

- **임시파일 → rename** 방식. 대상과 **같은 디렉터리**에 임시파일(예: `{파일명}.tmp-{nonce}`)을 UTF-8로 쓰고, `Files.move(tmp, final, ATOMIC_MOVE)`로 교체. `ATOMIC_MOVE` 미지원 파일시스템이면 `REPLACE_EXISTING` 폴백.
- 부모 디렉터리 생성(`Files.createDirectories`)도 **PathSafetyService 통과 경로 하위로만**.
- 쓰기 중 실패 시 임시파일만 남고 **최종 경로에 부분/깨진 파일이 남지 않는다**(임시파일은 실패 시 정리).
- 🔒 **심볼릭링크 거부(NOFOLLOW_LINKS)**: `resolveSafeWritePath`의 심볼릭링크 검증은 "최근접 **존재 조상**" 기준이라, 백업 시나리오처럼 **최종 파일이 이미 존재**할 때 그 최종 파일 자체가 심볼릭링크일 여지가 남는다. 따라서 임시파일 생성·`Files.move`·백업 복사·디렉터리 생성은 모두 `LinkOption.NOFOLLOW_LINKS`를 전제로 하며, **최종 대상 파일이 존재하고 심볼릭링크이면 하드 실패**(백업/덮어쓰기 거부)한다(`Files.readAttributes(..., NOFOLLOW_LINKS)`로 확인). 디렉터리 생성 후에도 최종 절대경로가 canonicalRoot 하위임을 쓰기 직전 1회 재확인(TOCTOU 축소).

### 5.2 덮어쓰기 / 백업 (기본 정책 = **`.bak` 타임스탬프 백업 후 덮어쓰기**)

- 기존 파일이 존재하면 **먼저 `{파일명}.bak-{yyyyMMddHHmmss}`로 백업**한 뒤 §5.1 원자적 교체로 덮어쓴다.
- 백업 대상은 **화면 3종 산출 파일**. 런타임 공통(1층위)은 §5.4대로 존재 시 skip(백업 없음).
- `.bak` 파일도 relativePath로서 §4를 통과해야 한다. 단 `.bak`는 확장자 화이트리스트 밖이므로 **백업은 PathSafetyService로 해석한 최종 절대경로를 기준으로 같은 디렉터리 내에서 수행**(원본 절대경로 + 접미사)하며, 백업 파일명 조립에도 자유문자열을 넣지 않는다(원본 파일명 + 정적 타임스탬프 접미사).
- 대안 정책(skip / 하드거부)은 채택하지 않는다(기본은 백업 후 덮어쓰기). diff UI·백업 브라우저는 P5/P6.

### 5.3 부분실패 판정 (RESULT_CODE)

`TB_FRG_GEN_HIST.RESULT_CODE`(NOT NULL: `SUCCESS`/`PARTIAL`/`FAIL`) 판정 기준:

| RESULT_CODE | 판정 조건 |
|---|---|
| `SUCCESS` | 계획된 아티팩트(§1.1) 전량 렌더+쓰기 성공. |
| `PARTIAL` | 일부는 성공했으나 1개 이상 렌더/쓰기 실패(경로안전 위반·렌더 오류 등). |
| `FAIL` | 전량 실패(0개 성공), 또는 컨텍스트 구성·입력 로드 단계 실패로 아무 파일도 못 씀. |

- 경로안전 통과 실패(`PathSafetyException`) 파일은 **즉시 실패 처리**(쓰지 않음). 타겟 루트 밖에는 아무것도 쓰지 않는다.
- 실패해도 이미 성공적으로 쓴 파일은 **롤백하지 않는다**(백업 존재로 복구 가능). PARTIAL로 판정하고 성공/실패 파일 목록·사유를 로깅.
- **성공/부분/실패 모두 GEN_HIST에 기록**(실패도 감사 대상, P4-5). `FILE_LIST_JSON`에는 실제로 쓴 파일의 상대경로(+선택적 해시) 목록을 Jackson으로 안전 직렬화(문자열 조립 0).

### 5.4 런타임 공통(1층위) 최소 정책 (P4-6 연계)

- 번들 런타임(commonList* 등, `header.jsp` 매니페스트)을 `TARGET_ROOT_PATH` 하위에 **존재하면 skip**(1회 복사). 화면 반복 생성 시 런타임 중복 생성 0. 복사 경로도 §4 통과. 버전관리는 P6.

**일반화 규칙(둘 중 하나, 둘 다 정적)**:
- **(권장) 컨텍스트 파생값**: 파이프라인이 listArea의 실제 `moduleTypeCode`를 `MODULE_ARTIFACTS`(§8.2)에서 조회해 얻은 **뷰 세트(nameSuffix)를 컨텍스트에 정적 파생값으로 실어** 템플릿에 넘긴다. 템플릿은 `<jsp:include page="./${stem}${listViewSuffix}.jsp" />`처럼 **화이트리스트 통과 파생값**만 이어붙인다(문자열 조립·평가 아님 — `listViewSuffix`는 `MODULE_ARTIFACTS` 값이지 자유문자열이 아니다).
- **(대안) 리터럴 case 분기**: 템플릿 내 `<#switch (slots["listArea"][0].moduleTypeCode)>` + **리터럴 케이스**(`TABLE_VIEW`/`CARD_VIEW`/`TREE_VIEW`/`FORM_VIEW`)로만 분기하고, 각 케이스는 **정적 리터럴 파일명**을 쓴다. `case` 외 값(default)은 **렌더 스킵**.

**금지**: `moduleTypeCode`로 파일명 문자열을 조립(`"List" + moduleTypeCode + ".jsp"`류)하거나 `?eval`/`?interpret`로 평가하는 것. §4.4·§2.3 위반 = reviewer blocker.

**listArea 단일 인스턴스 전제(MVP)**: `slots["listArea"][0]` 1건만 뷰 본문으로 렌더한다. **다중 뷰(뷰 전환 탭 = 한 listArea에 뷰 여러 개 + 전환 UI)는 P6**(뷰 전환 컨트롤러 확장). MVP는 listArea에 인스턴스가 2건 이상이면 [0]만 사용(초과분은 경고 로그 권장).

**미지원 moduleTypeCode = forward-compat 스킵**: listArea 인스턴스의 `moduleTypeCode`가 `MODULE_TYPE_WHITELIST`·`MODULE_ARTIFACTS`에 없으면 §2.2·§4의 forward-compat대로 **컨텍스트 구성 단계에서 스킵**(해당 인스턴스가 slots에 실리지 않음) → `list.ftl`은 listArea 본문 include를 **생략**(문서 전체 실패 0). 즉 **화이트리스트 미추가 뷰타입은 임의 산출 0**(§8.3).

### 8.3 🔒 신규 뷰타입 추가 체크리스트 (보안 핵심)

새 listArea 뷰타입(예: 향후 `CHART_VIEW`)을 추가할 때 **손대야 하는 4지점**. **(a)+(b) 둘 다 없으면 forward-compat 스킵되어 산출 0 = 무해한 미지원**(임의 파일쓰기 불가).

| # | 손대는 곳 | 파일/위치 | 안 하면? |
|---|---|---|---|
| (a) | `MODULE_TYPE_WHITELIST`에 코드 추가 | `TemplateContextBuilder` 103~104행 | 인스턴스가 컨텍스트 구성 단계에서 **스킵**(slots에 안 실림, 282~286행) → **산출 0** |
| (b) | `MODULE_ARTIFACTS`에 정적 매핑(3종) 추가 | `GenArtifacts` 64~71행 형식 | 아티팩트 목록에 안 잡힘 → **산출 0** |
| (c) | `.ftl` 3종 작성 | `templates/gen/module/{view}(Js/Css).ftl` | templateKey 해석 실패 → 렌더 실패(해당 뷰만 PARTIAL, §5.3) |
| (d) | V4 시드 + PROP_SCHEMA + 프리뷰 + 팔레트 | `V4__*.sql`, `docs/스키마_PROP_SCHEMA.md`, 스튜디오 | 스튜디오에서 배치 불가(정의 화면에 노출 안 됨) |

- **🔒 핵심 명문화**: `moduleTypeCode`는 **구조값**이다. `MODULE_TYPE_WHITELIST`(a)에 없는 코드는 §2.2·§4의 forward-compat대로 **스킵**되므로, **화이트리스트 미추가 = 임의 산출 0**이다. 개발자가 (a)+(b)를 명시적으로 추가하기 전에는 어떤 새 코드도 파일을 생성시킬 수 없다(공격자가 DEFINITION_JSON에 임의 `moduleTypeCode`를 넣어도 스킵). 이것이 신규 뷰 확장의 1차 신뢰경계다.
- **경로/파일명 재확인(변경 없음)**: 새 파일도 `{정적 nameSuffix}`+`stem`뿐(§4.2), 세그먼트는 정적+`role`+`stem`뿐(§4.3), 확장자 jsp/js/css 화이트리스트 내(§4.1). **§4는 신규 뷰에 그대로 적용되며 변경 없다.**
- **뷰코드/templateKey/nameSuffix 전부 정적 매핑 조회**: 위 3값은 `MODULE_ARTIFACTS`/매핑표(§8.1/§8.2)에서만 얻는다. `moduleTypeCode` 문자열로 조립·평가하지 않는다(§4.4 동형, AC (1) 충족).

### 8.4 🔒 뷰별 props 이스케이프 문맥표

DEFINITION_JSON §5 신뢰경계 그대로: **서버는 props 자유문자열을 이스케이프하지 않고, 소비자=템플릿(P5-2~4)이 산출 문맥별로 `GenEscaper`를 거친다.** 각 뷰 PROP_SCHEMA(V4, P5-4 확정 예정)의 대표 props를 문맥별로 분류한다.

> **⚠ 원본 확인 결과(중요)**: MagicIAM 런타임 3종(`commonListCardView.js`/`TreeView.js`/`FormView.js`)은 **뷰 데이터(카드 제목·트리 라벨·폼 필드)를 정적 props가 아니라 런타임 API 콜백**(`apiInfo.parser`/`renderCallback`/`features.getNodeData`)으로 받아 그린다. 즉 `titleField`/`labelField`/`fields[]` 같은 props는 **현재 런타임 JS에 존재하지 않는다**(아래 §8.6 근거표 참조). 따라서 아래 props는 **P5-4 PROP_SCHEMA에서 신규 정의할 "설정 props"**(어느 데이터 필드를 제목/라벨로 쓸지 등의 배선 힌트)이며, 이 표는 그 props가 산출 템플릿의 어느 문맥에 들어갈지의 **사전 이스케이프 계약**이다. 실제 props 키/기본값은 P5-4 시드 확정 시 이 표와 정합시킨다.

| 뷰 | 대표 props(설정값) | 산출 문맥 | 필수 이스케이프 함수 |
|---|---|---|---|
| **Card** | `titleField`/`subtitleField`/`imageField`(어느 데이터 키를 제목/부제/이미지로 바인딩할지 — 필드명) | JS 문자열(뷰 네임스페이스 config), `data-*` 속성(카드 템플릿) | `jsString`(JS), `htmlAttr`(속성) |
| **Card** | 정적 헤더/카테고리 라벨(있을 시) | HTML 텍스트 | `htmlText` |
| **Card** | `cardStyleClass`류 클래스 토큰(있을 시) | HTML `class` = CSS 토큰 | `cssToken`(화이트리스트) |
| **Tree** | `labelField`/`idField`/`parentField`(트리 라벨·노드ID·부모참조로 쓸 필드명) | JS 문자열(parser 배선 config), `data-*` 속성 | `jsString`(JS), `htmlAttr`(속성) |
| **Tree** | `rootName`(정적 루트 표시명, 런타임 `dataMapping.root.name` 대응) | HTML 텍스트(정적 루트 라벨) / JS 문자열(config) | `htmlText`(텍스트) / `jsString`(JS) |
| **Tree** | `rootIconClass`(런타임 `dataMapping.root.iconClass` 대응) | HTML `class`/이미지 파일명 조각 = CSS 토큰 | `cssToken`(화이트리스트) |
| **Form** | `fields[].name`(필드명·바인딩) | HTML 속성(`name`/`data-*`), JS 문자열 | `htmlAttr`(속성), `jsString`(JS) |
| **Form** | `fields[].label`(폼 라벨) | HTML 텍스트(`<label>`) | `htmlText` |
| **Form** | `fields[].type`(input 타입: text/select 등) | HTML 속성(`type="..."`) | `htmlAttr`(+ 값 화이트리스트 권장) |
| **Form** | `fields[].styleClass` | HTML `class` = CSS 토큰 | `cssToken`(화이트리스트) |

- 위 문맥·함수는 **전부 §3.2의 기존 4함수**(`htmlText`/`htmlAttr`/`jsString`/`cssToken`)로 커버된다. 문맥 종류(HTML 텍스트/HTML 속성/JS 문자열/CSS 토큰)는 TABLE_VIEW와 동일하며 **새 산출 문맥이 없다**.
- **🔒 신규 이스케이프 함수 필요 여부 판정**: **불필요.** Card/Tree/Form의 어떤 props도 §3.2 4함수 밖의 새 문맥(예: URL 문맥, JSON 문맥, `<style>` 값 문맥)을 요구하지 않는다. 이미지 경로는 런타임이 `/images/admin/{iconClass}.png`처럼 **고정 접두+토큰**으로 조립하므로 토큰만 `cssToken` 화이트리스트로 검증하면 충분하다(경로 자유문자열 0). 만약 P5-4에서 URL/href를 직접 받는 props가 새로 생기면 그때 URL 문맥 판정을 §8에 add-only로 추가한다(현재 스코프엔 없음).
- **원문 삽입 금지 원칙(§3.3)**: 위 props 중 하나라도 이스케이프 없이 원문 삽입되면 reviewer blocker(AC (2) — 이스케이프 누락 0).

### 8.5 Detail / Dual / Popup 계약 스텁 (후순위 정의만, MVP 밖)

> 아래는 **정의·근거만** 기록한다. 구현 아티팩트/템플릿은 **P5.5/P6**. 본 §8.5는 MVP 스코프 확정을 위한 판단 근거다.

**(1) Detail 슬롯(`detailBasic`/`detailTabs`/`detailToolbar`)** — 이미 `SLOT_WHITELIST["MGMT_LIST_DETAIL"]`에 등록됨(TemplateContextBuilder 91~93행):
- **렌더 위치**: shell(`{stem}.jsp`)의 **상세영역**. 현재 shell은 List 컨테이너만 배선(shell.ftl 22~24행). Detail 도입 시 shell에 상세 컨테이너(예: `<div id="{stem}-detail" class="detail-area">`)를 추가하고, `detailBasic`(기본정보 폼)/`detailTabs`(탭 그룹)/`detailToolbar`(상세 액션바)를 조건부 렌더한다. List↔Detail 전환은 MGMT_LIST_DETAIL의 마스터-디테일 UX.
- **아티팩트 형태(예상)**: List와 동형으로 detail 세트(jsp/js/css) 별도 산출 또는 shell 내부 조건부 렌더 중 택. **P5.5에서 확정**.

**(2) DUAL_LAYOUT 신규 아키타입** — `SLOT_WHITELIST["DUAL_LAYOUT"]={leftArea,rightArea}` 이미 등록(96~97행), `ARCHETYPE_ARTIFACTS`에는 **미등록**(MGMT_LIST_DETAIL만, GenArtifacts 47행):
- **아티팩트 형태(예상)**: `ARCHETYPE_ARTIFACTS`에 `DUAL_LAYOUT` 엔트리 추가(shell + left/right 컨테이너 List 세트). leftArea/rightArea 각각에 listArea류 뷰 배치. **P6에서 확정**.

**(3) 🔒 Popup 정체 판정 — "화면 내 조립 모듈"인가 "독립 화면 아키타입"인가**:
- **판정: 독립 화면 아키타입이 아니라, 기존 화면 위에 얹히는 "런타임 오버레이 유틸"에 가깝다.** J-FORGE 산출 관점에서는 **아키타입도 listArea 모듈타입도 아닌 별도 범주**로, MVP·P5 스코프에서 **제외**한다.
- **근거(원본 확인, [commonPopup.js](../src/main/resources/static/js/admin/common/commonPopup.js))**:
  - 파일 헤더(4~8행): "Popup UI에서 공통으로 사용하는 유틸리티… Popup의 popup이 발생할 수 있으므로 **context를 이용한 방식**으로 구현하여 중복 방지" — 팝업은 **여러 화면이 공유하는 컨텍스트 스택**(`const contexts = []`, 25행)이다.
  - `commonPopup.init(option)`(50~63행)은 `$container`/`header`/`body`/`footer`/`attribute`/`target`을 받아 **contexts 배열에 push**한다(61행). 즉 팝업은 **호출 화면의 DOM 위에 동적으로 여는 오버레이**이지, 자체 stem·라우트를 갖는 화면이 아니다.
  - `postMessage` 기반 부모-자식 통신(30~48행), `PopupType.width`(SMALL/MEDIUM, 65~70행)로 크기만 제어 — **화면 골격(shell/List)이 아니라 창(box) 위젯**.
  - FormView는 팝업 모드를 **런타임 메시지로 수신**(`event.data.type === 'SET_EMPTY_MODE' && mode === 'popup'`, commonListFormView.js 72~81행) — 팝업은 기존 뷰를 **감싸는 실행 컨텍스트**이지 새 뷰타입이 아니다.
- **결론**: Popup은 **P5 산출 대상 아님**. 필요 시 P6에서 "팝업으로 열리는 화면 = 일반 아키타입 산출물을 팝업 컨텍스트에서 로드"로 취급(별도 아키타입/모듈타입 신설 불필요). listArea 뷰 확장(§8.1~§8.4)과 **독립**이다.

### 8.6 MagicIAM 1:1 재현 근거표 (8장 — template-author용)

P5-2~4 template-author가 아래 **초기화 API 시그니처·필수 data-*/클래스명**대로 산출 JS/JSP를 배선한다(어긋나면 런타임 미동작). 시그니처는 **실제 런타임 JS에서 인용**(파일:라인).

## 14. 서버 바인딩 규칙 (P10) — stub → 조건부 실 Controller/Mapper/SQL 승격 (add-only)

> **부록 성격**: 본 §14는 P10 확정 부록이다. **§0~§13은 한 글자도 수정하지 않는다**(add-only). **보안 심장 무수정**
> (`ScreenGenerator`는 stub 생성 호출에 `model`을 넘기는 인자 1개만 추가 — 경로·쓰기 로직 무변경).
>
> **배경(P9 인계)**: §9 이후 `{stem}Design.js`(`common/design.ftl`)가 같은 도메인 API를 `fetch`해
> TABLE_VIEW 행까지 렌더한다. 그러나 타겟에 산출되는 Controller/Mapper/XML은 **빈 stub**(P4-6)이라
> 그 endpoint가 타겟 앱에 존재하지 않는다 → 생성 직후 화면은 **항상 404**. §14는 이 한 구간만 잇는다.

### 14.1 데이터 모델 (인스턴스 `data` 노드, add-only 예약 키 2종)

| 키 | 필수 | 게이트 정규식 | 의미 |
|---|---|---|---|
| `table` | 서버 바인딩의 **트리거** | `^[A-Za-z][A-Za-z0-9_]{0,62}$` | 조회 대상 테이블(DB 식별자) |
| `keyColumn` | 선택 | `^[A-Za-z][A-Za-z0-9_]{0,62}$` | 단건 조회 키. 있으면 상세 핸들러/`selectOne` 추가 |

기존 `endpoint`/`method`/`resultPath`/`autoLoad`(§5 저장 검증)는 그대로 재사용한다.

### 14.2 🔒 산출 게이트 (하나라도 실패 = 기존 빈 stub 그대로)

산출 소스는 **`listArea[0]` 인스턴스 1개**(단일 cardinality). 아래를 **전부** 통과해야 승격한다.

| 대상 | 게이트 | 실패 시 |
|---|---|---|
| `data.table` | 위 정규식 | 바인딩 없음 |
| `data.endpoint` | `^/[A-Za-z0-9/_-]{1,200}$` — §5 저장 검증(`SAME_ORIGIN_ENDPOINT`)보다 **좁힌 재검증**(점·공백·중괄호·확장자 불가) | 바인딩 없음 |
| `data.method` | `GET`\|`POST` 리터럴 | 바인딩 없음 |
| `data.resultPath` | 없거나 `^[A-Za-z][A-Za-z0-9_]{0,63}$` | 바인딩 없음 |
| `data.keyColumn` | 없거나 위 정규식 | 상세 핸들러만 생략 |
| `props.columns[].name` | 위 식별자 정규식 통과분만 채택(중복 제거, 1~100개) | 0개면 바인딩 없음 |

> **바인딩 없음 = P4-6 빈 stub 3종을 바이트 그대로 산출**한다. `data.table`이 없는 기존 화면은
> 산출이 1바이트도 달라지지 않는다(골든 무손상의 근거).

### 14.3 산출 규칙

- **경로·파일명·아티팩트 키는 불변**(§1.2/§4.3): `stubController`/`stubMapper`/`stubMapperXml` 3종 그대로.
  **내용만** 승격하므로 `GenPlanner` dry-run 계획(경로 목록)은 영향 0 — 드리프트 회귀망 무손상.
- **Controller**: `@RestController` + 클래스 레벨 `@RequestMapping("{endpoint}")`(게이트 통과 리터럴) +
  목록 핸들러(`method`에 따라 `@GetMapping`/`@PostMapping`) + `keyColumn` 있으면 상세 핸들러(`/{key}`).
- **응답 계약(§9 런타임 정합)**: `resultPath`가 있으면 `{ "<resultPath>": [...] }`, 없으면 배열 그대로 —
  `design.ftl`의 `valueAtPath(response, resultPath)`가 그대로 집어간다.
- **Mapper**: `selectList()` / (`keyColumn` 있으면) `selectOne(@Param("key") Object key)`. 반환은
  `List<Map<String,Object>>` / `Map<String,Object>`(타겟 DTO 규약에 독립).
- **XML**: `SELECT` **컬럼 명시**(`SELECT *` 금지, §계약 관례) + **`AS "COL"` 별칭 고정**.
  별칭은 대소문자 폴딩(PostgreSQL의 무따옴표 식별자 소문자화)을 막아 **응답 키 == `columns[].name` ==
  테이블 헤더 `data-name`** 을 성립시킨다 → `design.ftl`의 `renderTable`이 값을 찾는다.
  값 바인딩은 **`#{}`만**(`${}` 0).

### 14.4 🔒 안전

- 산출 코드에 들어가는 **모든 식별자·경로는 §14.2 게이트 통과분만**이다. 자유문자열(label/displayName 등)은
  Controller/Mapper/XML 어디에도 삽입되지 않는다 → 문자열 이스케이프가 아니라 **화이트리스트 통과 원본**만
  쓰므로 인젝션 표면이 없다(§3 이스케이프 정책과 상호보완).
- SQL은 식별자(테이블/컬럼) 결합 + `#{}` 파라미터뿐. 동적 SQL·`${}`·문자열 연산 0.
- 경로안전(§4)·원자적 쓰기(§5)는 기존 `StubGenerator` 경로 그대로(`resolveSafeWritePath` + `AtomicFileWriter`).
- **덮어쓰기 주의**: 승격된 Controller/Mapper/XML도 기존 stub과 동일하게 **재생성 시 덮어쓰기 대상**이다
  (§5.2 `.bak` 백업). 사람이 채운 로직 보존(보호구역 병합)은 §14 범위 밖 — 후속 페이즈.

- **§14 자기점검**: [x] `data.table` 없는 화면 stub 바이트 동일(전 골든 그린) · [x] 악성 식별자/경로 →
  승격 0(stub 폴백) · [x] `SELECT *` 0 · [x] `${}` 0 · [x] 경로/파일명 불변(GenPlanner 무영향) ·
  [x] 응답 형태가 §9 런타임 `resultPath`와 정합 · [x] §0~§13 정합(add-only).

## 15. 타겟 DB 스키마 조회 규칙 (P11) — 읽기전용 인트로스펙션 (add-only)

> **부록 성격**: 본 §15는 P11 확정 부록이다. **§0~§14는 한 글자도 수정하지 않는다**(add-only).
> **생성 파이프라인 무변경** — §15는 *설계 입력을 채우는* 경로일 뿐, 산출 경로를 건드리지 않는다.
> (생성기·보안 심장·템플릿·골든 전부 무관.)
>
> **배경(P10 인계)**: §14로 "테이블명만 알면 화면이 동작"이 됐지만, 그 테이블명·컬럼명을 **사람이
> 정확히 타이핑**해야 했다. 오타 하나면 런타임에 가서야 빈 목록으로 드러난다. §15는 그 입력을 없앤다.

### 15.1 🔒 접속 모델 — JDBC URL을 받지도, 저장하지도 않는다

| 항목 | 규칙 |
|---|---|
| 저장 위치 | `TB_FRG_PROJECT_DB`(프로젝트 1:1). `TB_FRG_PROJECT`는 **무변경**(자격증명이 일반 프로젝트 조회에 섞이지 않게 분리) |
| 저장 형태 | `host` / `port` / `database` / `schema` / `username` / `password(암호문)` — **URL 문자열 미저장** |
| URL 조립 | 서버가 `jdbc:postgresql://{host}:{port}/{database}`로만 조립. **쿼리스트링을 어떤 경우에도 붙이지 않는다** |
| host 게이트 | `^[A-Za-z0-9]([A-Za-z0-9._-]{0,253}[A-Za-z0-9])?$` — `/` `:` `?` `&` 전부 불가 |
| port | 1~65535 |
| database | `^[A-Za-z0-9_][A-Za-z0-9_-]{0,62}$` |
| schema / username | `^[A-Za-z_][A-Za-z0-9_]{0,62}$` / `^[A-Za-z_][A-Za-z0-9_.-]{0,62}$` |

> **왜 URL 자유입력을 금지하는가(핵심 근거)**: JDBC URL은 주소가 아니라 **드라이버 동작을 바꾸는
> 파라미터**를 실을 수 있다. PostgreSQL 드라이버의 `socketFactory`/`socketFactoryArg` 계열은 임의
> 클래스 로딩으로 이어지는 알려진 공격 표면이다. 조각만 받아 서버가 조립하면 이 표면이 **구조적으로
> 사라진다**(문자열 필터링에 의존하지 않는다).

### 15.2 🔒 조회 규칙 — SQL을 한 줄도 작성하지 않는다

- 테이블/컬럼/PK 조회는 전부 JDBC `DatabaseMetaData` API(`getTables`/`getColumns`/`getPrimaryKeys`).
  식별자는 문자열 결합이 아니라 **드라이버 인자**로 전달된다 → SQL 인젝션 표면 없음.
- 커넥션은 열자마자 `setReadOnly(true)`. **실패하면 연결을 포기한다**(안전측 수렴). 로그인 타임아웃 5초.
- 테이블명은 호출 전 식별자 화이트리스트로 한 번 더 거른다(방어 심층화 — 커넥션을 열기도 전에 거부).
- DDL/DML 실행 경로는 **코드에 존재하지 않는다**. 응답은 테이블/컬럼 메타뿐(행 데이터 조회 없음).
- 상한: 테이블 2000 / 컬럼 500.

### 15.3 🔒 자격증명 보관

- 비밀번호는 **AES-256-GCM**(JDK 표준, 외부 의존성 0)으로 암호화해 `base64(iv||ct)`로만 저장한다.
- 키 조달: 설정 `forge.secret.key`(base64 32B) → 없으면 `~/.j-forge/secret.key` → 없으면 **자동 생성**.
  전부 실패하면 DB 연결 기능이 **비활성**된다. **하드코딩 기본키·평문 폴백은 없다.**
- 비밀번호(평문·암호문)는 **어떤 API 응답에도 포함하지 않는다**. 수정 시 빈 값이면 저장분을 재사용한다.

### 15.4 자동 채움 규약 (§14와의 접합)

| DB 카탈로그 | → 화면 설계 |
|---|---|
| 컬럼명 | `props.columns[].name` — §14.3의 `AS "COL"` 별칭 규약과 그대로 맞물린다(응답 키 == 컬럼명 == 헤더 `data-name`) |
| 컬럼 주석(REMARKS) | `props.columns[].displayName`(없으면 컬럼명) |
| PK 컬럼 | `data.keyColumn` 기본 선택 → §14의 단건 조회 핸들러가 산출된다 |

| — | `data.endpoint`가 비어 있으면 화면 stem 기준 `/api/{stem}` 기본값(§5 저장검증이 endpoint를 필수로 보므로 빈 값 금지) |

## 16. 재생성 안전 규칙 (P12) — 해시·드리프트·diff·보호구역·복원 (add-only)

> **부록 성격**: 본 §16은 P12 확정 부록이다. **§0~§15는 한 글자도 수정하지 않는다**(add-only).
> `AtomicFileWriter`/`PathSafetyService`는 **0줄 수정**. `ScreenGenerator`는 결과에 해시를 싣는
> 한 줄만 바뀐다(쓰기 로직 무변경).
>
> **배경**: 생성물의 TODO를 채워 넣은 뒤 화면을 다시 생성하면 그 손길이 통째로 덮였다.
> `.bak` 백업은 남지만 **사용자는 덮였다는 사실조차 몰랐고**, dry-run은 "덮어쓰기 n건"이라는
> 숫자만 보여줬다. 코드 생성 도구가 실무에서 버려지는 가장 흔한 지점이다.

### 16.1 내용 해시 기록

- 생성 성공 시 쓴 내용의 **UTF-8 SHA-256**을 `GenFile.contentHash`에 담고,
  `GEN_HIST.FILE_LIST_JSON`의 각 항목에 `hash`로 남긴다(기존 키는 그대로 — add-only).
- 해시 대상은 `AtomicFileWriter`가 실제로 쓴 바이트다(보호구역 병합 **후** 내용). 그래야 왕복 비교가 성립한다.

### 16.2 드리프트 판정 (dry-run 확장)

`GenPlanner.PlanFile`에 `drift`가 추가된다(기존 `exists`는 그대로).

| 값 | 의미 |
|---|---|
| `NEW` | 타겟에 파일 없음(신규 생성) |
| `UNCHANGED` | 마지막 생성 이후 그대로 |
| `MODIFIED` | **사람이 손댔다** — 덮어쓰기 전 경고 대상 |
| `UNKNOWN` | 이력에 해시 없음(P12 이전 생성)·읽기 실패·과대 파일 |

- 기준값은 최근 이력(최대 20행)에서 경로별 **최신 해시**를 취한다.
- 🔒 판정에 필요한 읽기도 `resolveSafeWritePath` 통과 경로만 대상이며, **어떤 실패도 `UNKNOWN`으로
  수렴**한다(판정 불가가 생성 계획 실패로 번지지 않는다).

### 16.3 diff 미리보기 (읽기전용)

- `GET /api/screens/{id}/generate/diff?artifactKey=` → 현재 디스크 내용 vs **생성 예정 내용**의 줄 diff.
- 경로는 **`GenPlanner.plan` 결과에서만** 얻는다(실산출과 단일 소스). 계획에 없는 `artifactKey`는 **404** —
  임의 키로 경로를 만들어낼 수 없다.
- 생성 예정 내용은 **메모리 렌더**로만 만든다(디스크 쓰기 0). stub은 실산출과 같은
  `StubGenerator.contentFor` + `CustomRegionMerger`를 태워 **실제로 쓰일 내용**을 보여준다
  (보호구역만 채운 경우 diff는 "동일"로 나온다 — 미리보기가 거짓말하지 않는다).
- 성능 가드: 공통 앞/뒤를 잘라낸 구간이 1500줄을 넘으면 계산을 포기하고 `tooLarge`로 알린다.

### 16.4 보호구역(custom region)

```java
// <j-forge:custom id="body">
... 사람이 쓴 코드(재생성해도 보존) ...
// </j-forge:custom>
```

| 항목 | 규칙 |
|---|---|
| 적용 대상 | **Controller/Mapper/Mapper XML**(빈 stub·§14 승격 산출 모두). id: `body`/`methods`/`statements` |
| 주석 문법 | 자바 `//`, XML `<!-- -->` — 마커 토큰만 보고 줄 단위로 인식 |
| 보존 조건 | **새 내용에도 같은 id가 있을 때만** 옮긴다(사라진 구역의 옛 코드는 삽입하지 않는다 — 유령 코드 방지) |
| id 형태 | `[a-zA-Z][a-zA-Z0-9_-]{0,31}` 화이트리스트 |
| 실패 처리 | 중첩·미종료 구역은 병합하지 않고 **새 내용 그대로**로 수렴(경고 로그). 병합 실패가 생성 실패로 번지지 않는다 |
| 읽기 범위 | 방금 경로안전을 통과한 **그 경로 하나**만 읽는다(1MB 초과 시 병합 생략) |

> **골든 영향 0**: 골든 스냅샷은 `jsp`/`js`/`css`만 담는다. 보호구역은 **Java·XML 산출물에만**
> 들어가므로 기존 골든은 바이트 그대로다. **템플릿(JSP/JS/CSS)의 보호구역은 §16 범위 밖**이다 —
> 골든 전면 갱신을 수반하므로 별도 판단이 필요하다.

## 17. 자유 배치 아키타입 규칙 (P13) — FREE_CANVAS 절대좌표 (add-only)

> **부록 성격**: 본 §17은 P13 확정 부록이다. **§0~§16은 한 글자도 수정하지 않는다**(add-only).
> **보안 심장 무수정** — 새 확장자 0, 새 경로 규칙 0, 새 쓰기 경로 0.
>
> **배경(P8 인계)**: §13은 "드래그 제스처"를 줬지만 드롭 대상은 여전히 슬롯이었고 자유 좌표는
> 주지 않았다. §17은 P8 문서가 예고한 그 후속 — **기존 5개 아키타입을 건드리지 않고 6번째
> 아키타입으로** 델파이형 절대좌표 모델을 얹는다. 기존 화면의 산출은 1바이트도 달라지지 않는다.

### 17.1 아키타입 / 슬롯

| 항목 | 값 |
|---|---|
| `ARCHETYPE_CODE` | `FREE_CANVAS` (공통코드 시드 V10) |
| 슬롯 | `canvasArea` **1개**, cardinality **0..N** |
| 허용 카테고리 | `VIEW` `FILTER` `ACTION` `DETAIL` `WIDGET` `CONTROL`(신설) — 전부 |

배치 제약을 슬롯이 아니라 **좌표**가 대신하므로 카테고리 필터가 없다. `CONTROL`은 P13 신설
카테고리로 원자 컨트롤 4종(`BUTTON` `LABEL` `TEXT_INPUT` `IMAGE`)을 담는다.

### 17.2 데이터 모델 — 예약 숫자 키 5종 (§13 네이밍 계승)

인스턴스 `props` 안의 자유 키다 → **DEFINITION 구조 스키마 변경 0**.

| 키 | 유효범위 | 의미 |
|---|---|---|
| `layoutXPx` | 0 ~ 4000 | 시트 좌상단 기준 X |
| `layoutYPx` | 0 ~ 8000 | 시트 좌상단 기준 Y |
| `layoutWPx` | 20 ~ 4000 | 폭 |
| `layoutHPx` | 20 ~ 4000 | 높이 |
| `layoutZ` | 0 ~ 999 | 겹침 순서(기본 0) |

시트 크기는 DEFINITION **루트 `canvas` 노드** — `widthPx`(320~4000, 기본 1280) /
`heightPx`(240~8000, 기본 800). 저장 시 `DefinitionValidator`가 숫자·범위를 검증한다(노드가
없으면 검증 대상 아님 → 기존 화면 무영향).

> **X/Y/W/H 4키를 전부 통과해야** 그 인스턴스의 좌표 CSS를 산출한다. 하나라도 결여·비숫자·범위
> 밖이면 **그 인스턴스는 CSS 0바이트**(마크업은 정상 산출, 문서 흐름대로 배치) — 안전측 폴백.
> `layoutZ`는 독립 선택 키다(없으면 `z-index` 미산출).

### 17.3 🔒 셀렉터 전략 — instanceId를 CSS에 넣지 않는다

§13이 슬롯→셀렉터를 정적 리터럴 맵으로만 쓴 이유(자유문자열의 CSS 유입 차단)를 그대로 잇는다.
`instanceId`는 사용자 편집 가능한 DEFINITION 값이므로 **셀렉터에 쓰지 않는다.**

```
JSP  : <div class="frg-fc-item frg-fc-1"> … </div>   ← 1 = FreeMarker 루프 인덱스(데이터 아님)
CSS  : .frg-fc-1 { left: 24px; top: 80px; width: 320px; height: 180px; }
```

- 셀렉터 문자열 = **템플릿 리터럴 + 정수**. 데이터 유입 0.
- 값 = `?is_number` 게이트 + 범위 비교 통과 시에만 `?c` 포맷. **문자열은 어떤 경우에도 CSS에
  삽입되지 않는다**(악성값 `"100px;} body{"` → `?is_number` false → 0바이트).
- 인라인 `style=""`는 MagicIAM 3종 분리 규약을 깨므로 미채택.

### 17.4 🔒 산출 구조 — 항상 3파일 고정

> **왜 고정인가**: 파이프라인은 모듈 파일을 **모듈 타입당 1개**로 산출한다
> (`ScreenGenerator.allModuleTypeCodes`가 타입 기준 중복 제거, 파일명 = `stem` + 타입별 정적 접미사).
> `listArea`가 1..1이라 문제가 없었을 뿐, **0..N 슬롯에 같은 타입을 2개 놓으면 파일명이 충돌**한다.
> FREE_CANVAS는 모듈별 파일 분리를 하지 않음으로써 이 문제를 **구조적으로 회피**한다.

| 아티팩트 | 템플릿 | 파일명 |
|---|---|---|
| `freeCanvasShell` | `archetype/freeCanvas/shell` | `{stem}.jsp` |
| `freeCanvasJs` | `archetype/freeCanvas/shellJs` | `{stem}.js` |
| `freeCanvasCss` | `archetype/freeCanvas/shellCss` | `{stem}.css` |

- 캔버스 인스턴스 **본문 마크업은 shell.jsp 안에 인라인**(include 없음).
- 모듈 본문은 FREE_CANVAS 전용 파셜 `archetype/freeCanvas/item/*.ftl`. 기존 `module/*.ftl`은
  **무수정**(골든 무손상의 근거).
- 파셜이 없는 `moduleTypeCode`는 **스킵 + 자리표시 주석**(forward-compat 관례 동일).
- `MODULE_ARTIFACTS` 조회 경로를 타지 않으므로 캔버스에 어떤 모듈을 몇 개 놓아도 **산출 파일은 3개**다.

### 17.5 🔒 공통 런타임 CSS 충돌 방지

번들 공통 CSS(`commonListTableView.css` 등)는 `flex: 1 1 auto; min-height: 0` 같은 **부모 컨텍스트를
가정**한다. absolute 자식으로 직접 놓으면 깨지므로 **래퍼가 슬롯 부모를 흉내낸다**. 전부 per-screen
CSS에만 들어가며 **공통 CSS는 무수정**이다(§12 유지).

```css
.frg-fc-sheet { position: relative; width: …px; height: …px; }
.frg-fc-item  { position: absolute; display: flex; flex-direction: column;
                min-height: 0; overflow: hidden; box-sizing: border-box; }
```

`.frg-fc-item`이 flex 컬럼 + 고정 크기이므로 복합 모듈(TABLE_VIEW 등)의 부모 가정이 성립하고,
넘치는 내용은 클리핑된다.

### 17.8 중첩 컨테이너 규칙 (P13-7) — PANEL (add-only)

> §17.1~§17.7 무수정. 캔버스가 평면이라 "프레임 안에 테이블"이 안 되던 제약을 푼다.

- **컨테이너 모듈**: `PANEL`(카테고리 **`LAYOUT`** 신설, 시드 V11). `canvasArea`만 `LAYOUT`을
  허용하므로 **다른 아키타입 팔레트에는 나타나지 않는다**(기존 화면 무영향).
- **부모 참조**: 인스턴스 `props`의 예약 키 **`layoutParentId`**(부모 instanceId). 없으면 캔버스 루트.
  구조는 여전히 **평면 배열**이다 — `slots.canvasArea`에 모든 인스턴스가 그대로 들어 있어
  기존 순회(검증·컨텍스트·design 메타·instanceId 유일성)가 **무수정으로 동작**한다.
- **무결성 규칙**: 부모는 (a) 같은 canvasArea에 실존하고 (b) 컨테이너 타입이어야 하며
  (c) 자기 자신·순환이 아니고 (d) 최대 깊이 **3단계**(루트=1)를 넘지 않아야 한다.
  - **저장 시점**: `DefinitionValidator`가 위 4가지를 **하드 실패(400)** 로 잡는다 — 사용자가 원인을 안다.
  - **산출 시점**: `TemplateContextBuilder`가 같은 위반을 **루트로 수렴**시킨다 — 손상된 데이터가
    화면을 통째로 지우지 않는다(이중 방어).
- **좌표 기준**: 자식의 `layoutXPx/YPx`는 **부모 상자 기준**이다. 별도 좌표 변환 코드는 없다 —
  부모 `.frg-fc-item`이 `position:absolute`라 컨테이닝 블록이 자동 성립한다. 패널 제목은
  `position:absolute` 캡션이라 **자식 좌표 원점을 밀지 않는다**.
- **🔒 seq 단일 소스**: 중첩이 생기면 마크업 순서와 CSS 규칙 순서가 갈라질 수 있다. 그래서
  `TemplateContextBuilder`가 **`canvasTree`(깊이우선 전위순회 seq)** 를 한 번만 만들고
  `shell.ftl`/`shellCss.ftl`/`shellJs.ftl` **세 템플릿이 같은 트리를 읽는다** → 번호 드리프트 불가.
  셀렉터는 여전히 **정수 seq**이며 instanceId는 CSS에 들어가지 않는다(§17.3 유지).
- **삭제 규칙**: 컨테이너를 지우면 스튜디오가 **자손도 함께** 지운다(부모 잃은 인스턴스가 저장
  검증에 걸리는 것을 방지). 되돌리기는 undo.
- **경계**: 컨테이너는 현재 `PANEL` 하나다. 패널은 자식을 **클리핑**한다(`overflow:hidden`).

- **§17.8 자기점검**: [x] 중첩 DOM·부모 기준 좌표 산출 · [x] 순환/자기참조/미존재/컨테이너 아님/깊이
  초과 저장 거부 · [x] 같은 위반이 산출측에선 루트 수렴(화면 유지) · [x] seq 단일 소스(마크업·CSS 일치) ·

### 17.10 레이어 규칙 (add-only) — 컨테이너는 항상 자기 레이어 공간을 연다

> §17.1~§17.9 무수정. **발단(2026-08-07)**: 실제 산출물을 덤프해 보니 같은 중첩 구조가
> **부모의 `layoutZ` 유무에 따라 다르게 그려졌다.**
> `.frg-fc-item` 은 `position:absolute` 라, 부모에 `z-index` 가 붙은 경우에만 스태킹 컨텍스트가
> 생긴다 → 부모에 z 가 있으면 자식 z 가 부모 안에 갇히고(정상), **없으면 자식 z 가 루트와 직접
> 경쟁해 부모의 형제를 덮었다**(비정상). 사용자는 부모 z 를 건드린 적도 없는데 자식의 앞뒤가 뒤집힌다.

- **규칙**: 컨테이너(`CANVAS_CONTAINER_TYPES`, 현재 `PANEL`)의 래퍼는 **항상** 스태킹 컨텍스트를
  연다. 산출 CSS 는 정적 리터럴 한 블록이다 — `#{stem}-canvas .frg-fc-container { isolation: isolate; }`.
  `isolation` 은 `z-index` 를 건드리지 않고 컨텍스트만 만들므로 **좌표·크기 산출은 무영향**이다.
- **의미 확정**: 이로써 `layoutZ` 는 **"형제 사이의 순서"** 로 확정된다. 부모 밖으로 새지 않는다.
  델파이의 패널 모델과 같은 의미이며, **트리 구조라서 타 스택으로 이식 가능한 유일한 배치 정보**다
  (절대좌표·전역 z 는 이식 대상이 아니다).
- **마크업**: 컨테이너 래퍼에 `frg-fc-container` 를 **추가**한다
  (`class="frg-fc-item frg-fc-container frg-fc-N"`). 컨테이너가 아닌 인스턴스는 종전과 동일하다.
  판정은 `TemplateContextBuilder` 가 `canvasTree` 노드에 실은 `isCanvasContainer` 이며,
  **`moduleTypeCode` 화이트리스트(`CANVAS_CONTAINER_TYPES`)로만 정해진다** — 자유문자열 미개입.
- **🔒 셀렉터 불변**: 새 클래스는 템플릿 리터럴이다. 좌표 셀렉터는 여전히 정수 seq 이며
  `instanceId` 는 CSS 에 들어가지 않는다(§17.3 유지).
- **경계**: 컨테이너 래퍼는 `.frg-fc-item` 이고 `.frg-fc-panel` div 는 테두리·제목을 그리는
  **장식**이다(자식은 패널 div 의 형제로 래퍼 안에 놓인다). 클리핑도 래퍼의 `overflow:hidden` 이
  수행한다 — §17.8 의 "패널이 클리핑한다"는 표현을 이 문단이 정확히 한다(동작 변경 없음).

### 17.12 컨테이너 내용 상자 (add-only) — "상자 안 상자"

> §17.1~§17.11 무수정. **발단**: 자식이 패널 장식 div 의 **형제**로 래퍼 안에 놓여 있어,
> 생성물을 읽는 사람(과 타 스택 어댑터)에게 중첩이 "상자 안 상자"로 보이지 않았다.

- **구조**: 컨테이너 래퍼는 자식을 전용 내용 상자 `.frg-fc-panel-body` 안에 담는다.

```
.frg-fc-item.frg-fc-container   ← 좌표·클리핑·스태킹 컨텍스트(§17.10)
├─ .frg-fc-panel                ← 테두리/배경/제목 = 장식
└─ .frg-fc-panel-body           ← 자식이 사는 곳(position:absolute; inset:0; border:0)
   └─ .frg-fc-item …            ← 중첩
```

- **🔒 왜 패널 div 안에 직접 넣지 않는가**: `.frg-fc-panel` 은 테두리를 갖는다. 절대배치 자식의
  기준 상자는 위치 지정 조상의 **패딩 박스**이므로, 패널 안에 넣으면 자식 좌표가 테두리 두께만큼
  밀리고 **그 이동량이 `borderYn` 값에 따라 달라진다**(§17.10 에서 없앤 "관계없는 속성에 따라
  동작이 갈리는" 패턴의 재발). 내용 상자는 테두리가 없고 래퍼와 같은 사각형이라 **좌표가 그대로**다.
- **클리핑·스태킹 무변경**: 클리핑은 여전히 래퍼의 `overflow:hidden`, 스태킹 컨텍스트도 여전히
  래퍼의 `isolation:isolate` 다. 내용 상자는 `z-index` 를 갖지 않아 컨텍스트를 새로 열지 않는다.
- **컨테이너가 아닌데 자식이 있으면**(데이터 손상) 종전대로 래퍼 직계로 둔다 — 화면을 지우지 않는다.
- **들여쓰기**: 내용 상자가 한 겹이므로 자식은 조부모 대비 +8칸이다(컨테이너 8 → 내용 상자 12 →
  자식 16 → 내용 상자 20 → 손자 24).

## 18. 🔒 JSP EL 차단 규칙 (add-only) — 생성물은 JSP 다

> §0~§17 무수정. **§3.2 이스케이프 표를 대체하지 않고 강화**한다(htmlText/htmlAttr 처리문자 추가).
>
> **발단(2026-08-07, P13-6 골든 작업 중 발견)**: 기존 인젝션 골든에
> `<option value="c">${7*7}</option>` 가 **원시 그대로** 들어 있었다.
> `InjectionGoldenTest` 는 산출물에 `49`/`81` 이 없는지만 검사했는데, 그것은
> **FreeMarker 가 생성 시점에 평가했는지**만 보는 것이다. 산출물은 JSP 이고 생성 JSP 는
> `${ctx}` 를 쓰므로 **EL 이 켜져 있다** → 타겟 톰캣이 그 페이지를 렌더하는 순간 EL 이
> `${7*7}` 을 평가해 `49` 를 찍는다. 라벨 하나로 화면이 거짓말을 하고, EL 표현식에 따라서는
> 스코프 객체 접근까지 열린다. **"템플릿 인젝션 방지"(§0 보안 축)에 난 구멍이었다.**

- **규칙**: `htmlText`/`htmlAttr` 은 `$` → `&#36;`, `#` → `&#35;` 를 **무조건** 수행한다.
  엔티티이므로 브라우저 표시는 원래 문자 그대로다(표시 손실 0).
- **왜 조건부가 아닌가**: `$` 뒤에 `{` 가 올 때만 막으면 **인접 결합으로 우회된다** —
  템플릿에서 두 자유문자열이 나란히 찍힐 때 앞 값이 `$` 로 끝나고 뒤 값이 `{...}` 로 시작하면
  결합 결과가 `${...}` 가 된다. `jsString` 이 `<` 를 "문맥무관 견고"하게 처리하는 선례를 따른다.
- **jsString 은 대상 아님**: `jsString` 사용처는 전부 `.js` 아티팩트다(`design.ftl`,
  `*Js.ftl`). `.js` 는 JSP 로 파싱되지 않으므로 EL 대상이 아니다 — 종전 동작 유지.
  **단, 앞으로 JSP 안 인라인 `<script>` 에 `jsString` 을 쓰려면 이 규칙을 함께 적용해야 한다.**
- **cssToken 은 대상 아님**: 화이트리스트 `[A-Za-z0-9_-]` 라 `$`/`#`/`{` 가 애초에 통과 못 한다.
- **회귀망**: `GenEscaperTest` 에 EL 시퀀스·인접결합 우회·표시 무손실 케이스 추가.

  (템플릿 자신의 정적 `${ctx}` 는 제외 — htmlText 를 거치지 않는 리터럴이다).
- **골든 영향**: 인젝션 계열 골든 6파일에서 `${7*7}`/`${9*9}`/`#{2+2}` 가

## 19. 프레임에 화면 연결 규칙 (add-only) — LAYOUT_FRAME `frameSrc` → iframe src

> §0~§18 무수정. §10.3 이 예고한 그 후속이다 — *"향후 패인 URL 을 props 로 직접 받으면
> 그때 URL 문맥 판정을 add-only 로 추가한다."*

### 19.0 왜 "화면 참조"가 아니라 "경로"인가 (설계 판단)

착수 전 두 갈래를 검토했다 — (A) 다른 화면을 `screenId`/`stem` 으로 가리키고 생성기가 URL 을
조립 / (B) 같은 출처 경로를 값으로 받는다.

**(A) 를 기각한 이유: 이 제품에는 생성 화면의 페이지 URL 규약이 없다.**
`StubGenerator` 가 만드는 Controller 는 `// TODO: @RequestMapping 핸들러 추가` 인 빈 골격이고,
§14 로 승격되는 Controller 는 **데이터 API 용 `@RestController`**(`@RequestMapping("{endpoint}")`)다.
페이지를 어떤 URL 에 매핑할지는 **타겟 개발자가 직접 정한다.** 따라서 생성기가 `/{role}/{stem}`
같은 URL 을 지어내면, 개발자가 우연히 같은 매핑을 짰을 때만 맞는 **추측**이 된다(아니면 404).
없는 규약을 생성기가 발명하지 않는다.

→ **(B) 채택.** 값은 `props.frameSrc`(같은 출처 절대경로). 화면 참조가 필요해지면 그때
스튜디오가 **경로를 채워 주는 피커**를 얹는 게 맞다 — 저장되는 값은 여전히 경로다.

### 19.1 게이트 (단일 소스)

판정은 `templates/gen/common/frameSrc.ftl` 의 `safeFrameSrc(props)` **하나**다.
DUAL_LAYOUT 패인(§10.2)과 FREE_CANVAS 파셜(§17.9)이 이 함수를 `<#import>` 해서 공유한다
(규칙을 두 군데 적으면 갈라진다). §14 `data.endpoint` 의 **2층 검증**과 같은 구조다 —
저장측이 넓게 받고, 산출측이 **더 좁게 재검증**한다.

통과 조건(전부 만족):

| # | 조건 | 막는 것 |
|---|---|---|
| 1 | 문자열이다 | 타입 혼동 |
| 2 | `^/(?!/)[A-Za-z0-9/_.\-]{0,199}$` | `//evil.com`(프로토콜 상대) · `javascript:`/`data:`(콜론 불가) · 공백·역슬래시·따옴표·`?`·`&`·`%` |
| 3 | `..` 미포함 | 상위 경로 지시 |

- 통과 못 하면 **빈 문자열** → 호출측이 `src` 속성 **자체를 생략**한다(0바이트 폴백).
  §17.2 좌표 게이트·§17.4 파셜 미제공과 같은 안전측 관례이며, **원문이 새어나가는 경로가 없다.**
- 통과값도 최종 삽입은 `htmlAttr` 로 감싼다(심층방어).
- 산출 형태는 `src="${ctx}{frameSrc}"` — **컨텍스트 경로 접두는 템플릿 리터럴**이라
  절대 URL 이 통째로 들어갈 수 없다.

### 19.2 하위호환

`frameSrc` 가 없으면 **종전과 완전히 동일**하다(src 없는 빈 iframe). 따라서 기존 정의의 산출은
1바이트도 달라지지 않으며 **DUAL 골든 바이트 동일**이다. opt-in 확장이다.

### 19.4 프레임 파라미터 (add-only) — `frameParams` → 쿼리스트링

> §19.1~§19.3 무수정. **발단**: 프레임에 "게시판 목록"이 아니라 **"3번 부서의 게시판 목록"** 을
> 띄우려면 `?deptId=3` 이 필요한데 §19.1 게이트가 `?`/`&`/`=` 를 막고 있었다.

**정규식을 넓히지 않은 이유(두 가지).**

1. **`%` 가 함께 열린다.** 쿼리 값에 공백·한글을 넣으려면 퍼센트 인코딩이 필요한데, `%` 를
   허용하면 **글자 화이트리스트가 무력화된다** — `%2e%2e` 는 `..`, `%2f` 는 `/` 다.
   화이트리스트는 "이 글자만 통과"라는 전제 위에 서 있고, 인코딩을 허용하면 그 전제가 깨진다.
2. **값이 파라미터 경계를 깰 수 있다.** 사용자가 쓴 쿼리 문자열을 그대로 이어붙이면 값 안의
   `&`/`=` 가 새 파라미터를 만든다 — 값이 `A&admin=true` 면 받는 페이지는 **넣은 적 없는**
   `admin=true` 를 받는다(파라미터 밀수 → 권한 우회로 이어질 수 있다).

**그래서 문자열이 아니라 구조로 받는다.** 인코딩은 **생성기가** 한다.

```json
"props": {
  "frameSrc": "/admin/boardList",
  "frameParams": [
    { "name": "deptId", "value": "3" },
    { "name": "useYn",  "value": "Y" }
  ]
}
```

| 항목 | 규칙 |
|---|---|
| `name` | `^[A-Za-z][A-Za-z0-9_]{0,63}$` 화이트리스트 → 그대로 사용(URL 안전 문자뿐) |
| `value` | 문자열/숫자만. `?url('UTF-8')` 로 퍼센트 인코딩 → `&`·`=`·공백·한글이 전부 무해해진다 |
| 한도 | 최대 **20쌍**, 값 **200자** |

- **🔒 fail-closed**: 파라미터가 하나라도 어긋나면 **경로까지 통째로 버린다**(src 미산출).
  어긋난 것만 빼고 나머지를 붙이면, 빠진 것이 필터일 때 화면이 **의도보다 넓은 데이터**를
  보여준다(`deptId` 가 빠지면 전 부서가 나온다). **덜 보여주는 실패가 더 보여주는 실패보다 낫다.**
- **HTML 속성 문맥**: 조립된 URL 은 `htmlAttr` 을 거치므로 `&` 가 `&amp;` 로 나간다 —
  HTML 로서 올바르며 브라우저가 `&` 로 되돌려 요청한다.
- **하위호환**: `frameParams` 가 없으면 §19.1 과 완전히 동일하다(경로만 산출).
- **UI**: `frameSrc`(text)·`frameParams`(columns 반복행)를 LAYOUT_FRAME PROP_SCHEMA 에
  add-only 로 넣었다(시드 V13, 멱등). 속성 패널이 기존 렌더러로 그대로 그린다.
