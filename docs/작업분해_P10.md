성립시키면, P11은 그 테이블명·컬럼을 **손으로 안 넣게** 만드는 후속이다(의존 순서가 자연스럽다).

## 경계(알려진 제약) / 후속

- **목록·단건 조회까지.** 저장/삭제(INSERT/UPDATE/DELETE)와 검색조건(SEARCH_FILTER_BAR → WHERE),
  페이징(commonList 런타임 계약과 결합)은 P10 범위 밖 — add-only 후속.
- **`listArea[0]` 1개만** 바인딩. Detail(basic-info) 저장 배선, DUAL/POPUP/DASHBOARD는 후속.
- **재생성 덮어쓰기**: 승격 산출물도 사람이 채운 뒤 재생성하면 덮인다(`.bak`만 남음).
  보호구역 병합·드리프트 감지는 **P12**(재생성 안전)로 분리.
- **DB 인트로스펙션 없음**: 테이블명·컬럼명을 사람이 정확히 입력해야 한다 → **P11**.
- **컨텍스트 경로**: 생성 화면 런타임(`design.ftl`)은 `endpoint`를 **오리진 기준 절대경로로 그대로**
  `fetch`한다. 타겟 앱이 루트가 아닌 컨텍스트(예: `/myapp`)에 배포되면 `endpoint`에 그 접두사를 포함해
  입력해야 한다(`/myapp/api/users` — §14.2 게이트 통과 형태). 자동 접두는 P9 런타임 계약 변경이라 별도 판단.
- **컬럼명 == 응답 키 규약**: `columns[].name`이 곧 DB 컬럼명이자 JSON 키다(§14.3 별칭 고정).
  표시용 문자열은 `displayName`이 담당하므로 충돌하지 않는다.
