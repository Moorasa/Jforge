## 사용 흐름 (P10 + P11)

```
프로젝트 화면 → "DB 연결" → 접속정보 저장(연결 테스트로 확인)
   ↓
스튜디오 → 테이블 뷰 선택 → 속성패널 '데이터' 탭 → "테이블에서 가져오기"
   ↓  테이블 클릭 → 컬럼 체크 → 적용
data.table / data.keyColumn / props.columns 자동 · endpoint 기본값(/api/{stem})
   ↓  저장 → 파일 생성
Controller(@RequestMapping) + Mapper + SQL(컬럼 명시·별칭 고정) + 화면 3종  → 목록이 실제로 뜬다
```

## 경계(알려진 제약) / 후속

- **PostgreSQL 전용**. 다른 벤더는 URL 조립 규칙(§15.1)을 벤더별로 add-only 확장해야 한다.
  (`DB_TYPE_CODE` 공통코드에 자리는 이미 있다.)
- **접속정보는 프로젝트당 1개**. 개발/운영 등 복수 환경은 프로젝트를 나눠 쓴다.
- **읽기전용 계정 권장**: 코드가 읽기전용 세션을 강제하지만, 계정 권한 자체를 최소화하는 것이 정석이다.
- **오프라인 제약으로 실 DB 통합테스트 없음**: 로컬 Maven 저장소에 H2/HSQLDB가 없어 JDBC 계층을
  목킹해 검증했다. 실제 PostgreSQL 대상 스모크는 사용자 환경에서 "연결 테스트" 버튼으로 확인한다.
- **키 파일 권한**: POSIX 파일시스템에서는 `rw-------`로 제한하지만 Windows에서는 사용자 프로필
  권한에 의존한다(로컬 개발 도구 위협모델 기준).
- 컬럼 타입 → 폼 입력 타입 매핑(예: `date` → datepicker), FK 따라가기, 검색조건 자동 구성은 후속.
