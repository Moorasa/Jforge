# J-FORGE 작업분해 — P12 재생성 안전 (사람 수정을 삼키지 않는 생성)

> **PM 산출물(2026-07-30).** 선행: P0~P11 ✅.
> **발단**: P10/P11로 "생성 직후 동작하는 화면"이 됐다. 그러자 다음 위험이 전면에 나온다 —
> **개발자가 생성물을 고친 뒤 화면을 다시 생성하면 그 수정이 통째로 덮인다.**
> `.bak` 백업은 남지만 사용자는 덮였다는 사실조차 몰랐고, dry-run은 "덮어쓰기 n건"만 보여줬다.

  `ScreenGenerator`는 결과에 해시를 싣는 **한 줄**만(쓰기 로직 무변경).

  바이트 그대로다.

## 사용 흐름

```
파일 생성 → 개발자가 Controller 보호구역에 로직 작성 → (설계 변경) → 다시 "파일 생성"
   ↓
계획 모달: "외부 수정 2" 경고 + 파일별 "변경 보기"(줄 diff)
   ↓
생성 실행 → 보호구역 코드는 보존되고 나머지는 갱신
   ↓
그래도 잘못 덮었다면 → "백업에서 되돌리기"(시각 선택) → 복원(복원도 백업됨)
```

## 경계(알려진 제약) / 후속

- **템플릿(JSP/JS/CSS) 보호구역은 범위 밖**. 마커를 넣으면 골든 전면 갱신을 수반하므로 별도 판단이
  필요하다. 현재 보호 대상은 사람이 실제로 코드를 쓰는 **Java/XML**이다.
- **드리프트 기준은 빌더 DB의 이력**이다. 이력이 없으면(P12 이전 생성·이력 삭제) `UNKNOWN`으로
  표시되며 경고하지 않는다.
- **복원은 파일 1건 단위**다. "이 생성 회차 전체를 되돌리기"는 후속(이력 행 단위 일괄 복원).
- `.bak` 파일은 계속 쌓인다. 보존 기간·정리 정책은 후속.
- 병합은 **텍스트 기반**이다. 보호구역 밖에 쓴 코드는 여전히 덮인다(그래서 드리프트 경고와 백업 복원이
  함께 필요하다).
