> 컴포넌트가 놓이고, 드래그로 위치와 크기를 정하고 싶다."* P8은 **드래그 제스처**만 줬고

## 진단 요약 (2026-08-03 코드 확인)

델파이 모델과 현재 스튜디오의 실제 차이 5가지. ①②③은 의도된 설계(기획서 0장 2번),
④⑤는 미완/표류였다.

| # | 차이 | 근거 | P13에서 |
|---|---|---|---|
| ① | 캔버스가 폼이 아니라 **아키타입 슬롯 스택**(좌표 개념 없음) | `previewRenderer.renderDefinition` | 해소(신규 아키타입) |
| ② | 팔레트가 **현재 슬롯 호환 모듈만** 노출 | `palette.renderModules` | 해소(캔버스에선 전체 노출) |

## 확정 (2026-08-03 사용자 결정)

1. **부품 범위** — 복합 모듈까지 **전부 허용**(TABLE_VIEW·FORM_VIEW 포함) + 원자 컨트롤 신설.
2. **좌표 모델** — **px 절대좌표 + 고정폭 시트**. 반응형은 포기(델파이 폼과 동일). WYSIWYG 완전 일치.
3. **공존 방식** — **독립 아키타입으로만**. 기존 5개 아키타입은 무수정. 슬롯 내 자유영역 삽입은 미채택.

## 성격 / 불변

- 계약 **§17 부록**(add-only). **§0~§16 무수정.**
- **보안 심장 0줄 수정**: `AtomicFileWriter`·`PathSafetyService` 무변경.
  새 확장자 0(jsp/js/css), 새 경로 규칙 0.
- **골든 무손상**: FREE_CANVAS는 **신규 골든 세트**를 따로 갖는다. 기존 아키타입의 산출 경로·

- **XSS 규약**: 스튜디오는 계속 `createElement`/`textContent`만. 좌표는 숫자 게이트만.

## 🔒 계약 §17 초안 — FREE_CANVAS 자유 배치 규칙 (add-only)

### 17.1 아키타입 / 슬롯

| 항목 | 값 |
|---|---|
| `ARCHETYPE_CODE` | `FREE_CANVAS` |
| 슬롯 | `canvasArea` **1개**, cardinality **0..N** |
| 허용 카테고리 | `VIEW` `FILTER` `ACTION` `DETAIL` `WIDGET` `CONTROL`(신설) — 전부 |

기존 아키타입의 슬롯 표(§2.1~2.3)는 무수정. `ArchetypeSlots`/`slotMeta.js`/`TemplateContextBuilder`
세 곳에 **행 하나씩만** 추가한다(문서·서버·클라이언트 3중 미러 규약 유지).

### 17.2 데이터 모델 — 예약 숫자 키 5종 (§13 네이밍 계승)

인스턴스 `props` 안의 자유 키이므로 **DEFINITION 구조 스키마 변경 0**.

| 키 | 유효범위 | 의미 |
|---|---|---|
| `layoutXPx` | 0 ~ 4000 | 시트 좌상단 기준 X |
| `layoutYPx` | 0 ~ 8000 | 시트 좌상단 기준 Y |
| `layoutWPx` | 20 ~ 4000 | 폭 |
| `layoutHPx` | 20 ~ 4000 | 높이 |
| `layoutZ` | 0 ~ 999 | 겹침 순서(기본 0 = 배열 순서) |

화면 단위 시트 크기는 DEFINITION 루트의 **`canvas` 노드**(`widthPx` 320~4000 / `heightPx` 240~8000,
기본 1280×800). 루트 키 추가는 기존 검증이 허용하나 §17에서 **명시 검증을 추가**한다.

> **5키 전부 통과해야 그 인스턴스의 좌표 CSS를 산출**한다. 하나라도 결여·비숫자·범위 밖이면
> 그 인스턴스는 **CSS 0바이트**로 수렴(마크업은 그대로 흘러내림) — 안전측 폴백.

### 17.3 🔒 셀렉터 전략 — instanceId를 CSS에 넣지 않는다

§13이 슬롯→셀렉터를 정적 리터럴 맵으로만 쓴 이유(자유문자열의 CSS 유입 차단)를 그대로 잇는다.
`instanceId`는 사용자 편집 가능한 DEFINITION 값이므로 **셀렉터에 쓰지 않는다.**

```
JSP  : <div class="frg-fc-item frg-fc-1"> … </div>     ← 1 은 FreeMarker 루프 인덱스(데이터 아님)
CSS  : .frg-fc-1 { left: 24px; top: 80px; width: 320px; height: 180px; z-index: 0; }
```

셀렉터 문자열 = 템플릿 상수 + 정수. 값 = `?is_number` 게이트 + 범위 비교 + `?c` 포맷.
**문자열은 어떤 경우에도 CSS에 삽입되지 않는다**(§13과 동일 게이트). 인라인 `style=""`는
MagicIAM 3종 분리 규약을 깨므로 미채택.

### 17.4 🔒 산출 구조 — 항상 3파일 고정

> **왜 고정인가(P13 핵심 발견)**: 현재 파이프라인은 모듈 파일을 **모듈 타입당 1개**로 산출한다
> (`ScreenGenerator.allModuleTypeCodes`가 타입 기준 중복 제거 → 파일명 `{stem}+타입별 정적 접미사`).
> `listArea`가 1..1이라 문제가 없었을 뿐, **0..N 슬롯에 같은 타입을 2개 놓으면 파일명이 충돌**한다.
> (DASHBOARD `widgetArea`에 이미 잠재된 문제 — §17.7 후속에 기록.)
> FREE_CANVAS는 모듈별 파일 분리를 **하지 않음**으로써 이 문제를 원천 회피한다.

| 아티팩트 | 템플릿 | 파일명 |
|---|---|---|
| `freeCanvasShell` | `archetype/freeCanvas/shell` | `{stem}.jsp` |
| `freeCanvasJs` | `archetype/freeCanvas/shellJs` | `{stem}.js` |
| `freeCanvasCss` | `archetype/freeCanvas/shellCss` | `{stem}.css` |

- 캔버스 인스턴스의 **본문 마크업은 shell.jsp 안에 인라인**으로 찍는다(include 없음).
- 인스턴스 **초기화 JS는 `{stem}.js` 하나**에 인덱스별 블록으로 모은다.
- 모듈 본문은 FREE_CANVAS 전용 파셜 `archetype/freeCanvas/item/*.ftl` **신규 작성**.
  기존 `module/*.ftl`은 **무수정**(골든 무손상의 근거).
- 파셜이 없는 moduleTypeCode는 **스킵 + 경고**(기존 forward-compat 관례와 동일).

### 17.5 🔒 공통 런타임 CSS 충돌 방지 (복합 모듈 전부 허용의 대가)

`commonListTableView.css` 등 번들 공통 CSS는 `flex: 1 1 auto; min-height: 0` 같은 **부모 컨텍스트를
가정**한다. absolute 자식으로 직접 놓으면 깨진다. 해법은 **래퍼가 슬롯 부모를 흉내내는 것**이며,
전부 per-screen CSS에만 들어간다 — **공통 CSS 무수정**.

```css
.frg-fc-sheet { position: relative; width: 1280px; height: 800px; }
.frg-fc-item  { position: absolute; display: flex; flex-direction: column;
                min-height: 0; overflow: hidden; }
```

`.frg-fc-item`이 flex 컬럼 컨테이너 + 고정 크기이므로 복합 모듈의 부모 가정이 성립하고,
넘치는 내용은 클리핑된다. **캔버스에서는 W/H가 사실상 필수**(에디터가 배치 시 모듈별 기본
크기를 부여한다 — §17.2 폴백은 손상된 데이터용 안전망일 뿐).
