> 타겟 산출물(JSP)은 서버 실행이 있어야 화면이 되는데, 타겟 프로젝트는 스켈레톤+스텁이라 즉시 구동이 어렵다.

## 원리 — 빌더 톰캣이 생성 화면을 "대신" 렌더

생성 JSP 는 계약상 **스크립틀릿 0 / EL 은 `${ctx}` 하나 / JSTL 은 `c:set ctx` 하나 / include 는
시블링 아티팩트와 매니페스트(header.jsp)뿐**(§1/§3)이라, 서버 없이도 결정적으로 정적 HTML 로
변환 가능하다. 빌더는 이미 동일한 번들 런타임(jQuery+jworks+commonList*)을 서빙하므로:

1. DB 저장 DEFINITION → TemplateContextBuilder(검증 동일) → GenPlanner.planArtifacts(조립 규칙
   단일 미러) → TemplateRenderer 로 **메모리 렌더**(디스크 접근 0).
2. 변환: 시블링 `<jsp:include ./{stem}X.jsp>` 인라인 확장(깊이 가드) → 잔여 include 제거 →
   per-screen 자산 참조 제거 → 지시자/JSP주석/c:set 제거 → `${ctx}` 를 빌더 컨텍스트패스로 치환.
3. 래퍼 `run-preview.jsp` 가 **실제 `common/header.jsp` include**(동일 매니페스트) + 변환 본문 +
   per-screen CSS/JS 를 **asset 엔드포인트**(외부 파일 문맥 유지)로 주입 → 실제 런타임 JS 가
   브라우저에서 구동되는 "뜬 화면". 데이터 API 는 미연결이라 목록은 비어 있음(배너 고지).
